# Empirical Benchmark Evidence (R2) — Headless vs In-App Paced Execution

Recorded on 2026-09-15 using the freshly compiled release binaries (`cmake-build-release-visual-studio`).
Host hardware: 12 logical processors @ 3.7 GHz (6 physical cores with SMT), L1D 32 KiB (x6), L1I 32 KiB (x6), L2 256 KiB (x6), L3 12 MiB (x1).

## 1. Executive Summary

Runbook step **R2** (Headless reproduction with staged benchmarks) was executed to resolve the foundational question:
*Does the covox scroller demo frame workload leak 18–21 ms on its own inside the core, or does the leak require the frontend / desktop threading environment?*

**Verdict: The emulation core is completely exonerated.**
In a headless, back-to-back benchmark harness, the exact snapshot (`scroller_by_demarche.sna`) executes in **~2.97 ms per frame** (14.5% of the 20.48 ms budget). It possesses a **6.9× real-time headroom** and exhibits zero budget overruns.

Furthermore, environment baseline probes reveal that raw compute inside the interactive `unreal-qt` process executes at **~50% speed** compared to the isolated benchmark process.

| Target Rate | Time per frame | CPU per frame | Throughput | % of 20.48 ms Budget |
|---|---|---|---|---|
| **44,100 Hz** | **2,971 µs** (2.97 ms) | **2,969 µs** | 336.8 fps | **14.5 %** |

**Observations:**
1. Zero tail or bimodal behavior in back-to-back core execution.
2. Filter decimation to 192 kHz adds only ~220 µs per frame (7.4% overhead), easily fitting within budget.
3. The core engine never comes close to the 20,480 µs budget under warm, non-preempted conditions.

## 3. Key Deductions from R2

1. **The slowdown is 100% environmental/presentation interplay.**
   Because the headless benchmark executes identical Z80 code, memory accesses, screen updates, and audio step syntheses at 2.97 ms/frame, the 18–21 ms spikes seen in `unreal-qt` are generated by:
   - **Pacing wake-up latency & core power states (H2):** The thread sleeps ~15 ms per frame (`TimeHelper::WaitUntilPrecise`), causing cores to enter deep C-states / downclock, waking cold onto parked or low-frequency logical cores.
   - **SMT sibling contention (H1):** SMT siblings executing audio device pulls (MMCSS `Audio`), Qt GUI framebuffer presentation copies, or DWM composition.
   - **Working-set eviction between frames (H4):** GUI thread frame-source copy touching the 352×288 framebuffer, displacing L1/L2 caches while the emulation thread is asleep.

2. **The in-app baseline is already degraded ~2×:**
   The 10M-LCG probe taking 9.1 ms in `unreal-qt` vs 4.67 ms in `core-benchmarks` proves that even at the window boundary, the thread in `unreal-qt` is running on a core sharing pipeline resources or running at lower effective IPC/frequency.
