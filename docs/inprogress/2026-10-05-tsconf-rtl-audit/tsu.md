# TS-Conf TSU audit (tiles and sprites)

Scope: the TS-Conf tile and sprite unit (TSU) in unreal-ng, checked rule by rule against two references:

- **RTL** (authoritative): `fpga/current/...` in the zx-evo `pentevo` tree.
- **Unreal**: the TS-Labs Unreal Speccy fork, `Unreal/...` (cp1251 sources).
- **ng**: unreal-ng at master `cf3adb714`, paths `core/...`.

Verdicts: `match`; `ng-matches-RTL, Unreal differs`; `ng-matches-Unreal, RTL differs` (an ng bug); `ng differs from both` (an ng bug or a documented approximation); `unclear` (the reason is given). Where ng reads a value differs from RTL only in timing, the row says how large the effect is.

Build note: `T_CONFIG[0]` (`ts_rres_ext`) and `GFXOVR` exist only with `XTR_FEAT`. That define is off in the base build (`fpga/current/quartus/tune.v:18`) and on in the VDAC builds (`fpga/current/quartus_vdac/tune.v:16`, `fpga/current/quartus_vdac2/tune.v:13`).

The recent fix checks out. `TsConfTsu::LayerBounds` (`core/src/emulator/platforms/tsconf/tsconftsu.cpp:176-191`) ends S0, S1 and S2 at the first, second and third LEAP descriptors. A LEAP descriptor belongs to the layer it ends, LEAP also counts on inactive descriptors, and nothing after the third LEAP is processed. This is the same as RTL `video_ts.v:263-274` with `113-121` (the layer goes into `layer_skip`, and `s_layer` shifts out after S2) and as Unreal `init_sprite`, which sets `TSS_NOP` once `layer >= 2` (`Unreal/tsconf.cpp:642-649`, `768`).

## Bugs and gaps

**Row 49: latches change during the pass (ng-matches-Unreal, RTL differs).** RTL works on line L from `ts_start` of L-1 to `ts_start` of L. The `line_start_s` of L falls inside that span (`video_ports.v:153-165`), so tiles processed after it use L's T0/T1 G_PAGE, T0/T1 X offsets and PAL_SEL, not L-1's. ng (and Unreal) use the L-1 set for the whole line. This is visible only on heavy lines, where T1 or S2 work starts after about 448 - (hpix_beg_ts - 1) slots, and only when one of these registers changes on that line. Suggested test: `TsConfTsu_Test.TSU9_LateTilesUseTheNextLatch`. Give line L-1 a budget-saturating S0 (many 64-wide sprites), so T1 runs past the line start. Change T1_G_PAGE during L-1. Assert that T1 tiles drawn late in L take the new page. This needs a "work slot" model: the per-object position in the pass (`used`) compared with `448 - TsStartTact*2`.

**Row 40: TSU budget (ng differs from both, documented approximation).** The budget subtracts the CPU reads of line L-2 (`cpuLineAccesses` is set at `LineStart(L-1)`), not the CPU accesses concurrent with the pass, and it does not count CPU writes (`tsconfengine.cpp:93`). RTL gives the CPU every cycle it asks for (`arbiter.v:127,175-188`), writes included. A write-heavy CPU loop (LDIR to RAM) therefore leaves the TSU more slots in ng than on hardware. Suggested test: `TsConfEngine_Test.TSU8b_CpuWritesShrinkTheTsuBudget`. Run an LDIR on line L-1 with sprites filling about 400 slots. Assert that `Line(L).tsuCost` is at most `448 - videoCost - cpuAccesses(L-1, reads+writes)` and that the last sprite is dropped.

**Row 39: partial objects (ng differs from both, minor).** RTL and Unreal draw a sprite or tile that runs out of time up to the cut, 4 pixels per word. ng drops it whole, and `TSU8_StarvedObjectsAreDropped` asserts that. Suggested change and test: `TSU8_CutObjectIsDrawnUpToTheCut`. Use a 64-wide sprite with budget = used + 6. Assert pixels 0..11 drawn and 12..63 transparent (and the reverse side for XF).

**Row 48: SFILE write timing (ng differs from both, documented).** RTL reads descriptors progressively, so a CPU/DMA write landing after `ts_start` but before the TSU reaches that descriptor changes line L. ng snapshots at `ts_start`, so the change shows from L+1. This matters for sprite multiplexers timed near `ts_start`. Suggested test: `TsConfEngine_Test.TSU10_SfileWriteAfterTsStart`. Write descriptor 84 a few tacts after `ts_start` of L-1 while descriptors 0..83 are inactive (the scan reaches 84 about 21 slots in). Accept "L+1" as the documented ng behavior, or model the scan time (row 43) if exactness is wanted.

**Row 47: immediate registers read at a single instant (ng differs from both, documented).** This is the same mechanism as row 48 for T_CONFIG, T_MAP_PAGE, SG_PAGE and T0/T1_Y. `TSU6` pins the documented behavior. No new test unless the model changes.

**Row 30: tile count (ng differs from both, cost only).** RTL issues `x_tiles - 1` tile fetches per layer regardless of the X offset (33/41/46 in practice). ng fetches only tiles that intersect the window (32-33/40-41/45-46). ng therefore charges up to 2 accesses less per tile layer, so a line on the edge of starvation can keep one more object than on hardware. Suggested test: `TsConfTsu_Test.TSU8c_TileLayerCostFollowsXTiles`. Use T0 with all non-zero tiles, 256 wide, X & 7 = 0, and assert `used == 2*33` (RTL) rather than 64.

**Row 43: descriptor scan time (unclear).** Neither emulator charges the 28 MHz scan of descriptors that are off the line. It costs DRAM only when the renderer idles during a scan. No change suggested until a hardware capture shows it.
