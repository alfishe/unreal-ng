## 1. Точки входа ОС (куда ставить трапы)

| Точка | Что это | Где в сорцах |
|:--|:--|:--|
| `0x0010` (`RST #10`) | **Вызов DSS-функции**: номер в `C`, адрес обработчика берётся из таблицы `ADRST10` (младшие байты 0x0200, старшие 0x0300) | `DOS-MAIN.ASM:59` (A0010), `:120-128` (RST_10), `:250-299` (таблица) |
| `0x0008` (`RST #08`) | **Вызов BIOS**: команда в `C` (встречаются 16-битные коды в `BC`, например `#04C2`); `A0008` переключает страничку BIOS и делает `RET` — реальный обработчик в системной странице | `DOS-MAIN.ASM:53-57`, `:133-138` (ENTER) |
| `0x0000` | `JP LEAVE` — закрытие задачи (он же `EXIT` #41); удобная точка «баланс-проверки при выходе» | `DOS-MAIN.ASM:51`, `EXECUTE.ASM:1076` |
| `0x0038` | главный обработчик прерываний (клавиатура и т.д.) | `DOS-MAIN.ASM:79-108` |
| `0x0030` | `RST #30` — межстраничный вызов BIOS (используется самим DSS) | `DOS-MAIN.ASM:94` |

Функции, важные для отслеживания ресурсов (номера из `DSS.INC`, семантика из `docs/r_dsslist.htm`
и реализаций):

| # | Имя | Аргументы/результат | Реализация |
|:--|:--|:--|:--|
| #3C | INFOMEM | → HL=всего страниц, BC=свободно (BIOS #C0) | `EXECUTE.ASM:361-363` |
| #3D | GETMEM | B=размер блока в 16К стр. → A=ID блока, CF=0; иначе код 30 | `EXECUTE.ASM:368-380` |
| #3E | FREEMEM | A=ID блока; не владелец → код 31 | `EXECUTE.ASM:384-404` |
| #3F | SETMEM | A=ID, B=новый размер | `EXECUTE.ASM:409-454` |
| #38-#3B | SETWIN/1/2/3 | лог. страница блока → окно; BIOS #C4 | `EXECUTE.ASM:495-535` |
| #11/#12 | OPEN/CLOSE | файловый хэндл | `DOS5.ASM` |
| #40 | EXEC | загрузка и запуск EXE | `EXECUTE.ASM` |
| #41 | EXIT (=LEAVE) | B=код возврата | `EXECUTE.ASM:1076-1096` |
| #43 | GSWITCH | переключение задач (субфункция 7 `EX_PATH` #45) | `EXECUTE.ASM:104-135, 340` |
| #47 | APPINFO | B=0: командная строка, 1: путь, 2: полное имя (из PSP) | `EXECUTE.ASM:31-91` |

BIOS-команды, которые видит `RST #08` (по использованию в сорцах DSS; полный список —
`Docs/BIOS functions.asm` и `constants/BIOS_equ.inc` в **INC**, см. TODO):

`#C0` — статистика памяти; `#C2` — выделить блок страниц (B=размер → A=ID);
`#C3` — освободить блок; `#C4` — получить физ. страницу блока (A=ID, B=номер);
`#9D`/`#9E` — слить блоки при SETMEM; `#04C2` — «GET DSS PAGES HANDLE» — выделить
хэндл с страницами **в обход DSS-таблицы владельцев** (`DOS-MAIN.ASM:351-368`, DEPLOY).

## 2. Карта младших 16K (системная страница, `DSS_MAP.TXT`)

| Диапазон | Содержимое | Статус для охраны |
|:--|:--|:--|
| 0000-0038 | RST-векторы (0000 = LEAVE, 0008 = BIOS, 0010 = DSS, 0030, 0038) | checksum: неизменны после загрузки |
| 0066-0068 | NMI | checksum |
| 0080-0085 | межстраничный CALL-гейт | checksum |
| 0086-00C3 | BPB (параметры загрузочного диска) | watch при работающей задаче |
| **0100-01FF** | **MEMTAB — таблица владельцев памяти**: байт на ID блока = ID задачи (0 = свободен) | главный объект OS-aware; см. §3 |
| **0200-03FF** | **ADRST10 — таблица адресов DSS-функций** | checksum: приложение её переписывает → перехват ОС |
| 0400-043F | буфер клавиатуры | слабое наблюдение |
| 0440-0BD1 | драйвер клавиатуры; 0BD2-0EF5 драйвер экрана; 0EF6-1100 FAT; 1101-1342 disk I/O | checksum образа системной страницы |
| 1343-1443 | буфер текущего каталога | watch |
| **1444-16BD** | файловые хэндлы и файловый I/O (FM-таблица, см. §4) | объект OS-aware |
| 25C8-27AC | EXEC-процедуры; 27AD-2882 память; 2883-2CAE EXEC | — |
| **2EAF-2FAE** | PROCESS STACK BUFFER (`EXSTACK`) — сохранённые окна/стек родителя | watch в моменты EXEC/LEAVE |
| 2FAF-30CB | окружение (ENVIRON #46; данные на ENVPAGE=2 c #E400, `DOS-MAIN.ASM:30-37`) | — |
| 36E1-370D | DTA-буфер | watch |
| 3800-39FF | BUFFER/SECBUF | — |

Порча любого из «checksum»-диапазонов кодом задачи = порча системного добра, класс G playbook'а.

## 3. Память: три уровня владения

```
уровень BIOS:   хэндлы блоков 16К-страниц (RST #08 #C2/#C3/#C4/#04C2), таблицы в данных BIOS
уровень DSS:    MEMTAB[0100..01FF]: ID блока -> ID задачи (TASK)
уровень окон:   PAGE0=#82 (0000-3FFF, системная), PAGE1=#A2 (4000-7FFF),
                PAGE2=#C2 (8000-BFFF), PAGE3=#E2 (C000-FFFF)   [HARDWARE.INC:4-7]
```

- `GETMEM` (#3D): BIOS `#C2` выделяет B страниц → ID блока; затем `MEMTAB[ID]=TASK`
  (`EXECUTE.ASM:368-380`). Т.е. **владелец в MEMTAB — единственная DSS-видимость аллокации**.
- `FREEMEM` (#3E): проверяет `MEMTAB[ID]==TASK` (иначе ошибка 31 — «не твой блок»),
  BIOS `#C3`, обнуляет запись (`EXECUTE.ASM:384-404`).
- `SETWIN` (#38): по HL выбирает окно (BIT7/BIT6 H → PAGE1/2/3), BIOS `#C4` переводит
  логическую страницу блока в физическую, пишет порт, возвращает старое значение
  (`EXECUTE.ASM:495-535`).
- **LEAVE-семантика** (`EXECUTE.ASM:1076-1096`): сохранить код возврата → `LEAVMEM`
  (`:471-486`) — CPIR-проход по всей MEMTAB и `RETMEM` **каждого** блока текущей задачи →
  `TASK--` → восстановить окна PAGE1/2/3 и SP из PROCESS STACK BUFFER → `JP (HL)` в родителя.
  Выводы:
  - «забыл FREEMEM перед выходом» ОС прощает (подчистит LEAVMEM) — но это уже симптом
    небрежности, и детектор должен это показывать как warning;
  - **настоящий безвозвратный лик** — страницы, занятые после LEAVE: BIOS-хэндлы, взятые
    напрямую (`#C2` мимо DSS, `#04C2`), либо порча/потеря записей MEMTAB.

## 4. Файловые хэндлы (FM-таблица)

`DOS_FM.ASM`: `FMCOUNT=10` хэндлов, в 1.70 запись 44 байта (1.7X: `_sFM` 54 байта, FAT32-поля).
Ключевые поля: `HND1/2` (+38) номер хэндла, `FDRV` (+40) диск, `AMODE` (+41) режим,
**`FTASK` (+42) — задача-владелец**; далее позиция FP, кластер каталога и т.д.

- `OPEN` записывает текущий `TASK` в `FTASK` (`DOS5.ASM:280`);
- `CLOSE` требует `TASK==FTASK`, иначе ошибка 19 (`DOS5.ASM:305-308`);
- **LEAVE файловые хэндлы не закрывает и не проверяет** — выход задачи с открытыми файлами
  оставляет «мертвые» записи в FM. Класс C в playbook.

## 5. Процесс: PSP и якоря

`M_PSP` (`EXECUTE.ASM:1102-1164`) строит префикс программы в блоке образа:

```
PSP[-3] = EXE_FM  — файловый хэндл, которым загрузили EXE
PSP[-2] = EXE_MEM — ID блока памяти образа программы
PSP[-1] = TASK    — ID задачи
PSP[0]   = длина, затем командная строка, APP_PATH, APP_FULLNAME
LAST_PSP_PTR (дв. слово в данных DSS) — PSP последней запущенной программы
```

EXE-заголовок (`Estex-DSS/DSS/Structures.inc`, `_sEXE_HEADER`): `LD_ADDR` (адрес загрузки
#4100-#FFFF), `PC_REG`, `SP_REG`; точка возврата на `RETFAR → LEAVE` пушится загрузчиком
(`EXECUTE.ASM:1070-1074`).

`TASK` — одиночный байт текущей задачи в данных DSS (в 1.70 это, по сути, глубина вложенности
EXEC; переключение задач — `GSWITCH` #43). Для декодирования в отладчике адреса символов
`TASK`, `MEMTAB`/`MemoryTable`, `FM_BUF`, `XSTACK`, `ERLEVEL` берутся из экспорта сборки:
`system.exp` (`CORE_BUFFERS.*`, см. шапку) и `system.sym` — все 3 640 меток ядра
([estex-dss-build.md](../2026-09-28-sprinter/estex-dss-build.md) §3).

## 6. Системное «чистое состояние» (что сверять)

1. Векторы 0000-00FF и ADRST10 == эталон после загрузки DSS.
2. Каждая запись MEMTAB: 0 (свободно) или ID блока, существующего на уровне BIOS;
   сумма занятых страниц == всего − свободно (INFOMEM).
3. Каждая FM-запись: `FTASK` == 0/пусто или ID живой задачи; после выхода задачи — пусто.
4. Окна PAGE1-3 после LEAVE == снапшоту до EXEC; EXSTACK не тронут вне EXEC/LEAVE.
5. Нет страниц, «принадлежащих» BIOS-хэндлам, которых не видит MEMTAB, кроме
   известных системных (DSS-страницы DIRPAGE/FATPAGE/TXTPAGE/ENVPAGE/DRVPAGE,
   `DOS-MAIN.ASM:30-34`, и блоки DEPLOY `:351-381`).

Известные системные ловушки, иллюстрирующие классы порчи — `KNOWN.BUG`: `WINCOPY/WINREST`
не запрещают прерывания перед вызовом BIOS (вывод стеком — риск порчи стека DSS); ошибки
записи системных областей FAT/DIR молча теряются; «системные файлы пропускаются» при просмотре
каталога. Это готовые кейсы для мутационных тестов детекторов.
