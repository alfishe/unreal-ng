# Loader: MGT / IMG (DISCiPLE, +D, SAM Coupé raw dumps)

> Part of [2026-09-02-universal-track-model](README.md). Status: **implemented**
> (`core/src/loaders/disk/loader_mgt.{h,cpp}`, tests `core/tests/loaders/loader_mgt_test.cpp`).
> Not a Beta-disk format; supported because the geometry (10 × 512) is exactly the kind of track the model must
> hold, and +D/DISCiPLE ROM emulation may follow.

## 1. Format

Raw sector dump, 819 200 bytes: 80 cylinders × 2 sides × 10 sectors × 512 bytes. Sectors numbered 1..10, N = 2.

| Extension | Track order in the file |
|-----------|-------------------------|
| `.mgt` | cylinder-major, sides interleaved: c0/s0, c0/s1, c1/s0, … |
| `.img` | side-major: all c/s0, then all c/s1 |

No low-level information. Some dumps of 40-track disks (409 600 bytes) exist; detect by size.

## 2. Mapping to the model

`DiskImage(80, 2)`; each track `formatTrack(cyl, side, TrackFormatSpec::plusD())` — 10 × 512, gap3 chosen so that
10 × (10+12+3+7+22+12+3+1+512+2+gap3) + index gap ≤ 6250 (gap3 = 24 with 10-byte pre-ID gap fits at 6180); copy
512 bytes per sector, `recalculateDataCRC()`.

## 3. Save

Inverse: for sector numbers 1..10 per track write `getSector(n-1)->data` (512 bytes). Extension decides the track
order.

**Strict** (deviation from the first draft, which zero-filled missing sectors): the save is refused with a warning
in `lastWarnings()` unless every track carries exactly sectors 1..10 with 512-byte data fields, and the image has
2 sides and 40 or 80 cylinders (`LoaderMGT::isPlusDGeometry`). This mirrors `LoaderTRD::isTrdosGeometry` — a raw
dump cannot represent anything else, and silently zero-filling would hide the loss; UDI is the "save anything"
target.

## 4. API

```cpp
LoaderMGT loader(context, path);
loader.loadImage();                      // DiskImage(80|40, 2), every track plusD(), data copied, CRCs valid
loader.writeImage(path);                 // strict; order by extension of `path`
loader.setTrackOrder(TrackOrder::SideMajor); // override for callers without an extension (Auto = by extension)

LoaderMGT::detect(fileSize, extension);  // 819200 / 409600 and .mgt / .img (any case, dot optional, or a path)
LoaderMGT::cylindersForSize(fileSize);   // 80, 40 or 0
LoaderMGT::orderForExtension(pathOrExt); // .img => SideMajor, anything else => CylinderMajor
LoaderMGT::isPlusDGeometry(image, &reason);
loader.parse(data, len, order, warnings);            // in-memory, used by tests
loader.serialize(image, order, out, warnings);       // in-memory, strict
```

Track offset inside the file: cylinder-major `(cyl * 2 + side) * 5120`, side-major `(side * cylinders + cyl) * 5120`.

`loadImage()` sets the file path and the loaded flag and leaves the image clean; `writeImage()` marks the image
clean, posts `NC_FDD_DISK_WRITTEN` and updates the file path (same contract as UDI / TRD).

## 5. Findings

* `TrackFormatSpec::plusD()` fits: 10 sectors with gap3 = 0x18 total 6180 bytes ≤ 6250, the formatter produces
  sectors 1..10 with N = 2 and valid ID/data CRCs, and `getSector(n - 1)` resolves by sector number.
* The WD1793 reads the full 512-byte data field of sector 10 (last on the track) and of sector 1 on cylinder 79
  side 1 through `READ SECTOR` with `_beta128Register = BETA_CMD_RESET` (DENSITY bit clear = MFM). Sector 11
  ends in RNF, as it should.
* Because the model keeps whole tracks, `.mgt` → `.img` and `.img` → `.mgt` conversions are just "load, save with
  the other extension" and are byte-exact against the generator's output in both directions.
* A 409 600-byte buffer parses as 40 cylinders × 2 sides; the first 40 cylinders of an 80-cylinder cylinder-major
  dump are a valid 40-cylinder dump (used by the test).

## 6. Fixtures

`testdata/loaders/mgt/synthetic.mgt` and `synthetic.img` (819 200 bytes each, same disk in both orders) are
generated by `core/tests/emulator/io/fdc/tools/mgt_hobeta_generator.py`. Every sector is self-describing:
byte 0 = cylinder, byte 1 = `(side << 4) | sector`, byte i ≥ 2 = `(cyl·7 + side·13 + sector·3 + i) & 0xFF`, so a
track that lands on the wrong (cylinder, side) is caught by content, not just by size.
