## 1. File layout

```
Disk information block (256 bytes)
0x00  34  "MV - CPCEMU Disk-File\r\nDisk-Info\r\n"   (standard)
          "EXTENDED CPC DSK File\r\nDisk-Info\r\n"   (extended)
0x22  14  creator
0x30  1   number of tracks (cylinders)
0x31  1   number of sides
0x32  2   size of a track incl. 256-byte track info (standard only, all tracks equal)
0x34  …   extended: one byte per track = track size / 256 (0 = unformatted track), cylinder-major, side-minor

Track information block (256 bytes, at the start of every track)
0x00  13  "Track-Info\r\n"
0x10  1   cylinder
0x11  1   side
0x12  1   extended: data rate (0 unknown, 1 SD/DD, 2 HD, 3 ED)
0x13  1   extended: recording mode (0 unknown, 1 FM, 2 MFM)
0x14  1   sector size code N (all sectors, standard)
0x15  1   sector count S
0x16  1   GAP#3 length
0x17  1   filler byte
0x18  8×S sector info: C, H, R, N, ST1, ST2, [extended: actual data length, 2 bytes]
0x100     sector data, in list order; standard: 128<<N each; extended: "actual data length" each
```

uPD765 status bits that carry model information: ST1 bit 5 (0x20) data error in ID field → `idCrcValid = false`;
ST2 bit 5 (0x20) data error in data field → `dataCrcValid = false`; ST2 bit 6 (0x40) control mark → deleted DAM;
ST1 bit 2 (0x04) no data → ID-only sector; ST1 bit 0 missing address mark → ID-only.
Extended "actual data length" > 128<<N means multiple copies of a weak sector (usually 2–3): the loader keeps the
first copy as data and marks the bytes that differ between copies in the weak-bit bitmap.

## 2. Mapping to the model

Per track: `TrackFormatSpec spec; spec.sectorNumbers = R[]; sectorSizeCodes = N[]; sectorCylinders = C[];
sectorHeads = H[]; gapPostData = GAP#3; dataFill = filler; indexMark = true` (CPC/+3 tracks carry an IAM);
`encoding` from recording mode (default MFM); `trackLength` 6250 (grows when `!fits()`, warning).
Then copy data and apply status bits as above (`setDataAddressMark(0xF8)`, CRC corruption by flipping a CRC byte,
ID-only through `spec.idOnly[i]`). Unformatted tracks (extended size 0) → `resizeRaw(6250)` filled with 0x4E and
no sectors.

+3: 40 cylinders, 1 side, 9 sectors 1..9, N=2, GAP#3 0x2A (42), filler 0xE5. The `TrackFormatSpec::plus3()` preset
reproduces this and is used when creating a blank +3 disk (`LoaderDSK::createBlankPlus3Image()`).

## 3. Save

Extended DSK is always written (it is a superset). Per track: sector list from the index, N per sector, ST1/ST2 from
`idCrcValid/dataCrcValid/deleted/hasData`, actual length = `dataSize` (0 for ID-only), GAP#3 = measured gap after
the first data CRC, filler = most common data byte. Track length information and clock marks are lost (documented).

## 5. Findings (deviations from the design above)

- **ST1 bit 5 is not "ID CRC error" on its own.** The uPD765 sets ST1.DE (0x20) for *both* ID-field and data-field CRC
  errors and additionally ST2.DD (0x20) for the data field. Real CPC dumps therefore carry `ST1=0x20 ST2=0x20` for a
  data CRC error; mapping ST1 bit 5 literally to `idCrcValid = false` would make the WD1793 report RECORD NOT FOUND
  instead of a CRC error. Implemented: ST1.DE **without** ST2.DD → ID CRC invalid; ST2.DD → data CRC invalid. Saving
  writes ST1.DE|ST2.DD for a bad data CRC and ST1.DE alone for a bad ID CRC. A sector with *both* CRCs bad comes back
  with only the data CRC bad (the file format cannot express both).
- **ID-only detection** also honours ST2 bit 0 (missing data address mark) and an extended "actual data length" of 0.
  Saved as ST1 0x04 + ST2 0x01 with length 0.
- **Weak bits survive the round trip.** The design listed only track length and clock marks as lost; the writer stores
  a sector with weak bytes as two copies (second copy = first with the weak bytes inverted), so the loader's
  multi-copy path restores the same weak bitmap.
- **Index mark fallback.** When a layout misses 6250 bytes only because of the IAM (a TR-DOS style 16 × 256 track
  saved to DSK: 6208 + 146), the track is rebuilt without the index mark instead of being stretched. Growing is used
  only when the sectors themselves do not fit, up to `RawTrack::MAX_TRACK_SIZE` (12500); beyond that GAP#3 is reduced
  before refusing the track.
- **Sector size codes N > 3**: the WD1793 masks N to two bits, so the model holds 128 << (N & 3) bytes; the ID keeps the
  original N and a warning is emitted. Standard DSK images store 0x1800 bytes for N >= 6 (CPCEMU convention) - that
  is what the parser skips.
- **Filler on save** is the most frequent *data* byte of the track (0xE5 when the track has no data), not the gap byte -
  DSK's filler describes the formatted sector contents.
- **Track blocks are padded to a multiple of 256** on save, as the extended size table only holds size / 256.
- **Strict refusals** (load returns `nullptr` with a warning): unknown signature, missing `Track-Info`, more than 29
  sectors in one track info block, more than 86 cylinders or 2 sides, more than 204 tracks in an EDSK size table,
  truncated header / track info / sector data. Recording mode 1 loads the track as FM (3125 bytes, IBM 3740 gaps);
  the data rate byte is ignored.
- **Creator**: the writer always emits `unreal-ng     ` (14 bytes); the creator of a loaded file is exposed through
  `getCreator()` for information only.
- **Controller test setup**: in the WD1793 read-back test the Beta-128 port bit 6 (`BETA_CMD_DENSITY`) now selects
  FM, so an MFM read needs `_beta128Register = BETA_CMD_RESET` only; the track register and the drive's physical track
  must both equal the cylinder written into the ID fields (Type II commands compare C with the track register).
- **No real disk image** is used as a fixture - both files are generated by `dsk_image_generator.py` from
  deterministic byte patterns.
