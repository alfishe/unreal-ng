# Loader: TD0 (Sydex Teledisk)

> Part of [2026-09-02-universal-track-model](README.md). Status: **implemented** (read "TD" + "td", write "TD").
> Code: `core/src/loaders/disk/loader_td0.h/.cpp`. Tests: `core/tests/loaders/loader_td0_test.cpp`.
> Fixtures: `testdata/loaders/td0/` generated by `core/tests/emulator/io/fdc/tools/td0_image_generator.py`.

## 1. File layout (little-endian)

```
Image header (12 bytes)
0x00  2   "TD" normal, "td" advanced compression (whole file after the header is LZSS+adaptive Huffman, "LZHUF")
0x02  1   sequence (0 for single file)
0x03  1   check sequence
0x04  1   Teledisk version (e.g. 0x15 = 2.1)
0x05  1   data rate: bits 0-1: 0 = 250 kbps, 1 = 300, 2 = 500; bit 7 = FM (single density)
0x06  1   drive type (1 = 360K, 2 = 1.2M, 3 = 720K, 4 = 1.44M, …)
0x07  1   stepping: bits 0-1; bit 7 = comment block present
0x08  1   DOS allocation flag (1 = only DOS-allocated sectors were saved)
0x09  1   sides (1 = single sided, else 2)
0x0A  2   CRC-16 of the first 10 bytes (polynomial 0xA097, MSB first, init 0; the table in fdc.h `CRCHelper::crc16`
          is the same CRC stored byte-swapped - verified against a bitwise implementation, see Crc16_MatchesFdcTable)

Comment block (if header bit 7 set): CRC(2) length(2) year-1900 month-1 day hour minute second (6) text
   CRC covers length + date + text. Text lines are NUL separated (exposed as '\n' in the description).
Track header: sector count (0xFF = end of image), cylinder, head (bit 7 = FM track), CRC-8 (low byte of CRC-16 over 3 bytes)
Sector header: C, H, R, N, flags, CRC-8 (low byte of the CRC-16 over the *decoded* sector data; 0 when no data)
   flags: 0x01 sector was duplicated within the track, 0x02 data CRC error, 0x04 deleted DAM,
          0x10 DOS-unallocated (no data stored), 0x20 no data field (ID-only), 0x40 no ID field (rare)
Data block (present unless flags & 0x30): length(2, includes the encoding byte) then encoding(1):
   0 raw bytes; 1 = count(2) + 2-byte pattern repeated; 2 = RLE: blocks of [len l; l==0: count c, c raw bytes;
   l>0: count, then 2l-byte pattern repeated count times]
```

## 2. Mapping to the model

Identical to FDI once sectors are decoded (`LoaderTD0::buildTrackSpec`): `TrackFormatSpec` from the sector list
(order, N, C, H), format, copy data, apply flags (`0x04` → F8 data mark, `0x02` → data CRC bytes inverted,
`0x10 | 0x20` → `spec.idOnly`), `encoding = FM` when the track head byte has bit 7 or the header data-rate bit 7 is
set. The MFM template is `TrackFormatSpec::trdos()` (6250 bytes, gap3 60); the FM template is
`TrackFormatSpec::ibm3740()` (3125 bytes, 0xFF gaps, sync 6, gap3 27). When the sectors do not fit, gap3 shrinks
to the datasheet minimum (16 MFM / 10 FM) and then the track grows up to `RawTrack::MAX_TRACK_SIZE`.
Data rate 300/500 kbps is outside the WD1793/Beta-disk envelope: loaded with a warning, track length scaled
(`6250 × rate/250` → 7500 / 12500, FM 3750 / 6250), clamped to `MAX_TRACK_SIZE`.

Other rules:
- Geometry comes from the track headers: cylinders = max cylinder + 1, sides from the header byte (a head-1 track
  in a "single sided" file promotes the image to two sides with a warning). Tracks absent from the file and tracks
  with 0 sectors stay unformatted (`resizeRaw`, 6250 bytes MFM / 3125 FM).
- `0x01` (duplicate) needs no special handling: the model keeps both sectors in stream order; the writer sets the
  flag again for the second and later sectors that repeat a number.
- `0x40` (no ID field) sectors are skipped with a warning (their data block is still consumed).
- Size code > 3 is masked to 2 bits with a warning (like FDI; the WD1793 cannot address bigger sectors);
  size code > 6 is invalid and the sector is skipped.
- Errors (parse returns nullptr): bad signature, header CRC mismatch, truncation anywhere inside the comment /
  track / sector / data structures, cylinder ≥ `MAX_CYLINDERS`, head > 1, a track that cannot fit even at
  `MAX_TRACK_SIZE`. A missing final 0xFF marker is a warning only.
- Warnings only: comment / track-header / sector-data CRC mismatches (many real images have stale CRCs),
  malformed data blocks (decoded output is zero padded), non-250 kbps rate, DOS-allocation flag set.

Decompression ("td"): `decompressLzhuf()` implements Okumura's LZHUF from the algorithm (`LzhufDecoder` in the
.cpp, ~200 lines): 4 KB ring buffer pre-filled with spaces, matches 3..60 bytes, 314-symbol adaptive Huffman tree
(FGK sibling-property updates, halving rebuild at root frequency 0x8000), match positions as a canonical 3..8-bit
prefix code for the upper 6 bits (1/3/8/12/24/16 codes per length) plus 6 raw bits. Teledisk streams carry no
length prefix, so decoding runs until the input is exhausted; the parser stops at the 0xFF marker and ignores any
trailing padding symbols. The whole body is decompressed into memory (cap 64 MB) and parsed like a "TD" file.

## 3. Save

`serialize()` / `writeImage()` produce the uncompressed "TD" variant: header (version / drive type / stepping /
data rate preserved from the loaded file, defaults 0x15 / 3 / 0 / 0; header FM bit set only when every track is
FM), comment block when a description is set (date fields preserved from the loaded file, `'\n'` → NUL),
one track header per (cylinder, head) including empty tracks, data encoding 1 for sectors that are a repeated
2-byte pattern and encoding 0 otherwise (encoding 2 is never written), flags `0x01/0x02/0x04/0x20` from the
model, 0xFF terminator. Like FDI it is lossy for gaps, clock marks, exact CRC values, ID CRC errors and
non-nominal track lengths (one warning). `writeImage()` marks the image clean, sets its file path and posts
`NC_FDD_DISK_WRITTEN`. Advanced ("td") compression is not written.

## 6. Findings

- `CRCHelper::crc16` in `fdc.h` is the Teledisk CRC: its table is the MSB-first 0xA097 table with every entry
  byte-swapped and the state kept swapped, which the final `_byteswap_ushort` undoes. The loader uses its own
  bitwise form (const input, size_t length); the test proves both agree.
- The sector CRC-8 is computed over the decoded data, not the packed block; the data block length includes the
  encoding byte. Both were confirmed by the round trip through the independent Python writer.
- The LZHUF position tables (`d_code` / `d_len`) do not need to be copied: they are the canonical prefix code for
  the length histogram 1/3/8/12/24/16 over lengths 3..8, so both the C++ decoder and the Python encoder build them
  at start-up.
- Adaptive-Huffman tree rebuilds (`MAX_FREQ`) are exercised by the fixture: the raw LCG sectors are incompressible
  and push the root frequency past 0x8000 several times; the "td" fixture still decodes byte-exactly.
- Deviations from the first design: a writer was added (uncompressed "TD" only, so round-trip tests and TRD → TD0
  conversion exist); the comment date is preserved as a field; size codes above 3 are masked like FDI instead of
  refusing the image; a missing 0xFF terminator is tolerated.
