# 8BitAnalysers (Spectrum Analyser) debugger — capability survey

**Source:** https://github.com/TheGoodDoktor/8BitAnalysers · local checkout commit `dc6accc4` (2026-01-26) · C++17, Dear ImGui (docking branch) + ImPlot on GLFW/OpenGL3 (DX11 on Windows), Lua 5.x scripting · emulator core = `TheGoodDoktor/chips` (a fork of floooh's header-only `chips`: `systems/zx.h`, cycle-stepped pin-level `chips/z80.h`, `ay38910.h`, `beeper.h`) driven by a local tick loop `ZXChipsImpl.c`
**Surveyed:** 2026-09-28 (source reading; `Source/Vendor/*` submodules are not checked out locally, so statements about chips internals are marked *(inferred)*)
**Scope note:** A GUI-only reverse-engineering workbench, not a classic monitor. The core is a shared, CPU-agnostic "code analyser" (`Source/Shared/CodeAnalyser`, used by the ZX, C64, CPC, BBC and Tube Elite front ends) that builds per-byte code/data/label/comment/reference metadata while the game runs, plus a debugger (breakpoints, stepping, watches, call stack, event trace) and many viewers. ZX-specific parts live in `Source/ZXSpectrum`. There is no console monitor, no expression language, no remote protocol (no GDB stub / DeZog / socket); automation is in-process Lua only. Models: 48K and 128K only.

## 2. Emulator core and the analysis hook

- **Core.** `FSpectrumEmu` owns a chips `zx_t ZXEmuState` plus a backup `zx_t` for edit mode (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.h:154-155`). The model enum has only `Spectrum48K` and `Spectrum128K` (`:42-46`). Submodule is `TheGoodDoktor/chips` with `update = merge`, a fork of floooh chips (`8BitAnalysers/.gitmodules`).
- **Tick loop.** `ZXExeEmu()` replaces chips' `zx_exec`: per T-state tick it calls `_zx_tick`, a floating-bus patch, an IM2 hack (`if (cpu.step == 1490) dlatch = 0xff`), and then the debug callback, and it stops mid-frame as soon as `*sys->debug.stopped` is set (`8BitAnalysers/Source/ZXSpectrum/ZXChipsImpl.c:73-105`). So breaks are tick-precise, not frame-granular.
- **Per-tick analysis.** `DebugCB` -> `FSpectrumEmu::Z80Tick(pins)` (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:469-473`, `:247-421`) decodes the Z80 pin mask: MREQ+RD -> `RegisterDataRead`, MREQ+WR -> `RegisterDataWrite` + `SetLastWriterForAddress` + screen pixel/attr events; IORQ -> port-decoded events and device hooks; on `z80_opdone` -> `OnInstructionExecuted` -> `RegisterCodeExecuted`; finally `CodeAnalysis.OnCPUTick(pins)` -> `FDebugger::CPUTick` for breakpoint/step checks (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyser.cpp:1461-1480`).
- **Frame boundaries.** Machine frame start/end are derived from `scanline_y` changing to `0` / to `frame_scan_lines` (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:256-267`). `CurrentFrameNo` (the clock for all heat maps and "recently executed" fades) advances in `OnMachineFrameEnd` only while running (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyser.cpp:1453-1459`). The host loop runs `1e6 / hostFPS * ExecSpeedScale` µs of emulation per UI frame (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:1811-1856`), so the instruction trace (cleared per *host* frame in `FDebugger::StartFrame`, `8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:366-370`) and the event list (cleared per *machine* frame, `:348-354`) use different frame notions.
- **Not emulated.** Memory contention is explicitly absent (`FIXME: 'contended memory' accesses should inject wait states`, `8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:273`). The floating bus returns the attribute byte of the current *line* only (`8BitAnalysers/Source/ZXSpectrum/ZXChipsImpl.c:33-50`), no per-T-state fetch sequence.

## 3. Analysis data model (the heart of the tool)

- **Banks and pages.** Memory is split into 1 KiB `FCodeAnalysisPage`s holding, per byte: `FLabelInfo*`, `FCodeInfo*`, an inline `FDataInfo`, `FCommentBlock*`, scope label, `FMachineState*` (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalysisPage.h:24-45`). Pages belong to `FCodeAnalysisBank`s (ROM 0/1, RAM 0..7 on 128K; 16 KiB each, `8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:741`, `:750`), mapped into separate read and write page tables (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyser.h:682-691`). 128K port `7FFD` writes remap the analysis banks live (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:376-392`, `:431-457`).
- **Addresses.** Everything user-facing is an `FAddressRef {int16 BankId; uint16 Address}` packed into 32 bits (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyserTypes.h:186-215`), so labels, breakpoints, watches, references and trace entries are bank-aware. `FixupAddressRefs` passes repair them after bank changes (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:1617-1642`).
- **Reference tracker.** `FItemReferenceTracker` keeps up to 32 distinct `FAddressRef`s; linear duplicate check, then overwrite round-robin (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyserTypes.h:234-289`). Used for label callers, data readers/writers, instruction read/write targets, IO-device accessors.
- **Per byte (`FDataInfo`).** DataType (byte, word, arrays, text, bitmap, charmap, screen pixels, image, blob, col-attr, instruction operand, struct, flags), display type, flags (game-state, bit-7-terminated, binary, char map, struct member, breakpoint), `ReadCount/LastFrameRead/LastRead`, `WriteCount/LastFrameWritten/LastWritten`, `Reads`, `Writes`, `LastWriter` (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyserTypes.h:441-523`). Reads of addresses that are code are not registered (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyser.cpp:1065`).
- **Per instruction (`FCodeInfo`).** Disassembly text, operand type/address, `FrameLastExecuted`, `LastExecuted`, `ExecutionCount`, flags (disabled, SMC, is-call, Lua handler, breakpoint), NOP backup bytes, `Reads`/`Writes` trackers (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyserTypes.h:384-422`).
- **Discovery.** `AnalyseAtPC` writes code info on first execution, generates Function/Code labels for jump/call targets and Data labels for pointer indirections, tags operand bytes as `InstructionOperand` pointing back to the instruction (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyser.cpp:807-887`, `:890-954`). A write to an operand byte sets `bSelfModifyingCode` on the owning instruction (`:1091-1098`). Static walk-ahead (`AnalyseFromPC`) stops at already-formatted data (`:958-973`).
- **Z80-specific runtime analysis.** `RegisterCodeExecutedZ80` tracks `LD SP,nn/HL/IX/IY/(nn)` sites, CALL/RET for the call stack and function call/exit points, and on every PUSH/CALL writes the pushing instruction's comment onto the stack slot and formats the slot as a word (`8BitAnalysers/Source/Shared/CodeAnalyser/Z80/CodeAnalyserZ80.cpp:234-405`). Stack extent is inferred incrementally from SP (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:310-321`).

## 4. Breakpoints and step control

- **Storage.** `std::vector<FBreakpoint>` with `{FAddressRef Address; int Val; EBreakpointType Type; bool bEnabled; uint16 Size}` (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.h:50-61`). Types: Exec, Data, Irq, NMI, In, Out (enum order is part of the save format, `:34`). `Val` is the port mask for In/Out (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:195-210`).
- **Keeping it cheap.** Two filters before any list scan: (1) per-byte flags `FCodeInfo::bHasBreakpoint` / `FDataInfo::bHasBreakpoint` set for every covered byte when a BP is added (`:655-677`); (2) a `BreakpointMask` rebuilt each host frame from enabled BP types (`:372-405`). Exec BPs are checked only when the executed instruction's flag is set (`:255-271`); data BPs only when the accessed byte's flag is set and the mask matches (`:149-164`). Then a linear scan of all BPs.
- **Keying.** Exec: exact `FAddressRef` equality with PC (bank + address). Data: same bank and `Address <= a < Address+Size`; read and write both trigger (`:174-182`). No hit counters, no conditions, no ignore counts.
- **Step modes.** `EDebugStepMode {None, StepInto, StepOver, ToCursor, Frame, ScreenWrite, IORead, IOWrite, Interrupt, NMI}` (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.h:20-32`). Step Over disassembles at PC and, for `CALL`, `CALL cc`, `DJNZ`, `HALT`, `LDIR`, sets `StepOverPC = next PC` (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:555-623`); other opcodes (incl. RST, LDDR, CPIR) fall back to Step Into. Step Frame breaks at the next machine frame end (`:356-364`). Step Screen Write breaks on the tick of the first write inside `FMemoryAnalyser::ScreenMemory` (`:111-117`).
- **Hotkeys.** F5 break/continue, F10 step over, F11 step into, F6 step frame, F7 step screen write, F9 toggle BP on cursor item (exec for code, data of item size for data) (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyser.cpp:1414-1419`, `8BitAnalysers/Source/Shared/CodeAnalyser/UI/CodeAnalyserUI.cpp:750-792`). Toolbar also has "<<< Trace" / "Trace >>>" and a "Trace Functions" checkbox (`8BitAnalysers/Source/Shared/CodeAnalyser/UI/CodeAnalyserUI.cpp:1505-1557`).

## 5. Tracing, events and the frame trace

- **Event record.** `FEvent {uint8 Type; uint16 Address; uint8 Value; uint16 ScanlinePos; FAddressRef PC}` (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.h:84-94`). `ScanlinePos` is `zx_t::scanline_y` — a line number only, no T-state or X position (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:257`). Types are registered with name, ABGR color and optional address/value renderers (pixel byte as 8 squares, attribute as ink/paper swatch, `8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:1311-1362`; registrations `8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:790-802`).
- **Port decoding for events.** Reads: `A0=0` keyboard; `A7..A5=000` Kempston; any other port with low byte != 0 floating bus; 128K `11xx..x0x` AY read. Writes: `A0=0` border/beeper/MIC — each only when that bit field *changes*; 128K `A15=0,A1=0` bank switch (unless paging locked); AY select/write (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:321-402`).
- **Per-scanline strip.** `ScanlineEvents[320]` stores the last event type per scanline; Spectrum View paints a colored tick per line to the right of the screen (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:859`, `8BitAnalysers/Source/ZXSpectrum/Viewers/SpectrumViewer.cpp:65-74`). Selecting an event row highlights its scanline in the event color; hovering sets a flashing highlight line (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:1458-1477`, `8BitAnalysers/Source/ZXSpectrum/Viewers/SpectrumViewer.cpp:86-97`). The screen coordinate mapping offsets by `top_border_scanlines - 32` because the displayed border is smaller than the real one (`:63`, `:78`).
- **Event window.** Filter per type (Select All/None), "Clear Every Frame", "Write Comments"; table Scanline / Type / PC / Address / Value, ImGui list clipper (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:1363-1513`).
- **Frame Trace viewer.** 300-entry ring of `FSpeccyFrameTrace`: RGBA screenshot texture, `MemoryBanks[8][16K]`, `MemoryBankRegister`, malloc'd `z80_t`, `InstructionTrace` (copy of the debugger's per-host-frame PC list), `FrameEvents` (`8BitAnalysers/Source/ZXSpectrum/Viewers/FrameTraceViewer.h:45-57`, `8BitAnalysers/Source/ZXSpectrum/Viewers/FrameTraceViewer.cpp:54-83`). About 128 KiB RAM + texture per slot, so roughly 40+ MiB for the ring *(inferred)*. UI: arrows + "Backwards Offset" slider (scrubbing breaks execution), "Restore" (copy CPU, RAM, 128K paging back and continue), "Restore On Scrub"; tabs Instruction Trace (SMC-aware re-disassembly), Trace Overview (nearest Function/Code label sequence), Screen Writes, Diff (`:119-211`).
- **Instruction trace format.** Not a text log: rows are `FAddressRef`s rendered as `ADDR mnemonic` with markup (`8BitAnalysers/Source/ZXSpectrum/Viewers/FrameTraceViewer.cpp:213-259`). There is no file export of traces or events.

## 6. Video, beam and graphics tooling

- **Beam position.** Only a scanline-granular indicator: when stopped and "Scan Line Indicator" is enabled, a line with arrows at `scanline_y` (`8BitAnalysers/Source/ZXSpectrum/Viewers/SpectrumViewer.cpp:75-83`, option `8BitAnalysers/Source/Shared/Misc/EmuBase.cpp:456`). No T-state/X readout, no contention view.
- **Provenance on the screen.** Hovering the display shows the last pixel-writer and attribute-writer PCs straight from `FDataInfo::LastWriter` (`8BitAnalysers/Source/ZXSpectrum/Viewers/SpectrumViewer.cpp:409-422`); the ZX Graphics Viewer "Screen" tab has the same tooltip (`8BitAnalysers/Source/ZXSpectrum/Viewers/ZXGraphicsViewer.cpp:45-58`). Hovering an address anywhere in the UI (`HighlightAddress`) outlines the matching pixel byte or attribute cell on the screen (`8BitAnalysers/Source/ZXSpectrum/Viewers/SpectrumViewer.cpp:136-160`).
- **Heat maps.** One color rule reused everywhere: yellow = executed, red = written, green = read within N frames, else white (`8BitAnalysers/Source/Shared/CodeAnalyser/UI/GraphicsViewer.cpp:189-218`). Thresholds: Graphics viewer 4 frames (`8BitAnalysers/Source/Shared/CodeAnalyser/UI/GraphicsViewer.h:114`), Overview 16/8/4 (`8BitAnalysers/Source/Shared/CodeAnalyser/UI/OverviewViewer.cpp:130`, `:332`, `:389`). Memory access grids (char maps, 6502 zero page) fade read (green) / write (red) outlines over 32 frames (`8BitAnalysers/Source/Shared/CodeAnalyser/UI/MemoryAccessGrid.cpp:66-94`).
- **Graphics viewer.** Address slider over 64K or a bank, X/Y size in pixels (Y fine adjust), view modes listed in §1, bitmap format + palette (for CPC/C64 formats), graphics sets saved to `GraphicsSets.json` and exported as PNG sheets (`8BitAnalysers/Source/Shared/CodeAnalyser/UI/GraphicsViewer.cpp:522-1060`, `:1263-1445`). Sprite lists from the game config (`SpriteConfigs`) are generated at project load (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:888`).
- **Character maps.** A char map is `{Address, Width, Height, Stride, CharacterSet, IgnoreCharacter, FlagSet}` drawn through a char set that can carry interleaved masks and color info (`8BitAnalysers/Source/Shared/Util/GraphicsView.h:69-141`); the grid shows per-cell reads/writes and lists reader/writer PCs for the selected cell (`8BitAnalysers/Source/Shared/CodeAnalyser/UI/MemoryAccessGrid.cpp:176-200`).

## 7. Scripting (Lua)

- Lua is re-initialised per project; the project's `LuaSourceFiles` are loaded after the core and ZX libraries (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:1026-1051`). Base scripts ship in `8BitAnalysers/Data/SpectrumAnalyser/Lua` (`LuaBase.lua`, `ZXBase.lua`, `ViewerBase.lua`, templates, docs).
- **Execution handlers.** `RegisterExecutionHandler(addr, "fn")` sets `bHasLuaHandler` on the instruction; on execution the function is called and a `true` return breaks the debugger (`8BitAnalysers/Source/Shared/LuaScripting/LuaSys.cpp:217-273`, `8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyser.cpp:982-983`). This is the only way to get conditional breakpoints.
- **Drawing hooks.** `OnScreenDraw(x, y, scale)` after the Spectrum View image (overlays on the live screen), `Viewers` table entries with `name`/`onDrawUI` become tabs of a "Game Viewers" window, `OffScreenBufferHandlers` supply `Draw` and `GetAddressOffsetFromPos` (`8BitAnalysers/Source/Shared/LuaScripting/LuaSys.cpp:275-548`). Function docs are loaded from JSON and missing docs are warned about (`8BitAnalysers/Source/Shared/LuaScripting/LuaDocs.cpp:100-125`).
- No Lua access to breakpoints, stepping, events or the trace (API list at `8BitAnalysers/Source/Shared/LuaScripting/LuaCoreAPI.cpp:572-605`).

## 8. Persistence and interchange

- **Layout.** New-style project dir `Workspace/<Game>/` with `Config.json`, `Analysis.json`, `GraphicsSets.json`, `AnalysisState.bin`, `SaveState.bin`; old style uses `Configs/`, `AnalysisJson/`, `AnalysisState/*.astate`, `SaveStates/*.state` (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:920-958`, `:1063-1083`). ROM analysis comes from a bundled RomInfo json and can be written back ROM-only (`:962-965`, `:1106-1108`).
- **`Analysis.json`.** Per bank/page: labels (name, type, global, references), code info (operand type, struct id, SMC), data info (type, display type, flags, char-set/graphics-set/instruction refs, palette), comment blocks; plus data types, function info (params, return values, call/exit points, stub flags), character sets/maps (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalysisJson.cpp:28-186`, `:483-770`).
- **`AnalysisState.bin`.** Magic `0xBeefCafe`, version 2; per used non-ROM page (`0xDeadCafe` + page id): label reference lists (`addr|0x8000`), data read/write lists and `LastWriter` (`addr|0x4000`), terminator `0xFFFF`; then the debugger block (version 4): watches, breakpoints (address, enabled, type, size, val), frame trace, PC, scanline BP (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalysisState.cpp:7-228`, `8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:415-528`). The access provenance therefore survives across sessions.
- **Game config.** `FZXSpectrumGameConfig`: 128K flag, viewer config, sprite configs, cheats; `.pok` loaded from the Pokes folder (`8BitAnalysers/Source/ZXSpectrum/ZXSpectrumGameConfig.h:47-60`, `8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:958`). Global config: workspace/snapshot/pokes/RZX folders, font, scales, number mode, branch lines, Lua base files (`8BitAnalysers/Source/Shared/Misc/GlobalConfig.h:10-43`, `8BitAnalysers/Source/ZXSpectrum/ZXSpectrumConfig.h`).
- **RZX.** Input-recording block parsed (fetch counter + IN values per frame) and replayed by counting opcode fetches (prefixes count extra) with IN values injected (`8BitAnalysers/Source/ZXSpectrum/SnapshotLoaders/RZXLoader.cpp:233-265`, `8BitAnalysers/Source/ZXSpectrum/ZXChipsImpl.c:112-150`, `8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:1844-1849`). `EReplayMode::Record` exists but no recording path is wired *(inferred: only playback is referenced in `Tick`)*.

## 9. Notable and unique ideas

1. **Per-byte access provenance, bank-aware and persisted.** Every byte knows up to 32 reader PCs, 32 writer PCs and its last writer; every instruction knows what it read and wrote. Clicking through "who wrote this pixel / attribute / stack slot" is the core workflow and it survives save/load. Directly relevant to a ZX debugger's memory view.
2. **Screen-pixel -> code navigation.** Hover a screen cell to see the pixel and attribute writer PCs, double-click to jump; hover a data address to outline its cell on the screen. Cheap to build on top of a last-writer table.
3. **"Step Screen Write" (F7).** A one-key semantic breakpoint: stop on the next write to VRAM. Generalizes to "step to next IO write / bank switch / border change" (the enum already has those modes).
4. **Scanline-tagged hardware event log with a color strip beside the screen.** Border, beeper, MIC, AY, paging, keyboard/Kempston/floating-bus events with PC, rendered as a per-scanline color bar; selecting an event flashes its line. A per-T-state version would be a natural upgrade.
5. **Frame-decay heat maps everywhere.** One rule (exec/write/read within N frames) reused in the graphics viewer, screen view, char-map grids, overview map and code-line activity markers.
6. **Automatic code/data discovery with SMC detection.** Execution drives disassembly, labels (Function vs Code by CALL vs JP), operand tagging, and SMC flags; the listing becomes an annotated source you can export to sjasmplus/SkoolKit.
7. **Stack slot annotation.** On PUSH/CALL the pushing instruction's comment is copied to the stack slot and the "Set by" column shows the writer, so the stack view explains itself.
8. **Function parameter / return capture.** User-declared register params and return values are sampled on every call/return (16-entry history) — lightweight dynamic function profiling.
9. **Frame Trace ring (300 frames) with screenshots and restore.** A poor-man's rewind at host-frame granularity with per-frame instruction trace and trace overview.
10. **Screen-cell graphic finder.** Click a character cell, search all banks for its 8 bytes, format as bitmap, open in the graphics viewer.
11. **Lua execution handlers as scripted breakpoints + `OnScreenDraw` overlays + per-game viewer tabs.** Game-specific tooling without recompiling.
12. **Edit Mode sandbox.** Snapshot on enter, restore on exit: pokes and opcode edits are experiments by default.

## 10. Gaps and caveats

- **IN/OUT/IRQ/NMI breakpoints cannot fire.** `bpMaskCheck` is only ever set to the data-read/write bits (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:149-159`), so the `bpMaskCheck & BreakpointMask` gate (`:164`) never admits the IO/IRQ/NMI cases (`:184-211`). `Out` also sets `BPMask_IORead` instead of an IO-write bit (`:392-393`). No UI or Lua path creates these types, and the breakpoint list labels anything but Exec/Data as "Unknown" (`:1254-1265`).
- **Data breakpoints** do not distinguish read from write, have no value conditions and no hit counts (`:174-182`).
- **Scanline breakpoint is not wired on the Spectrum**: `OnScanlineStart` is called only by the C64 and Tube Elite front ends (`8BitAnalysers/Source/C64/C64Emulator.cpp:996`, `8BitAnalysers/Source/TubeElite/TubeElite.cpp:783`).
- **"Break on pixel write"** adds a data BP of 8 *contiguous* bytes at the cell's top pixel row (`8BitAnalysers/Source/ZXSpectrum/Viewers/SpectrumViewer.cpp:317`), but the cell's 8 rows are 256 bytes apart in Spectrum VRAM, so it covers the top row of 8 adjacent cells instead of the selected cell *(inferred from the Spectrum screen layout)*.
- **Frame Trace "Screen Writes" and "Diff" tabs are empty**: `ScreenPixWrites` is never filled and `GenerateMemoryDiff` is commented out (`8BitAnalysers/Source/ZXSpectrum/Viewers/FrameTraceViewer.cpp:78-79`, `8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:1860`). Restore copies only CPU, RAM and the paging latch — not ULA/AY/beeper/scanline state (`8BitAnalysers/Source/ZXSpectrum/Viewers/FrameTraceViewer.cpp:86-117`).
- **Two frame notions.** The instruction trace and frame-trace capture are per host UI frame (emulated time scales with host FPS and the speed slider), while events and `CurrentFrameNo` are per machine frame (see §2). The machine-frame end is detected as `scanline_y == frame_scan_lines`; whether the chips fork ever exposes that value is not verifiable here (submodule not checked out) *(inferred risk)*.
- **No timing fidelity for beam work.** No contention, floating bus per line only, events tagged with scanline number only, beam indicator only when stopped, displayed border smaller than real (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:273`, `8BitAnalysers/Source/ZXSpectrum/ZXChipsImpl.c:33-50`, `8BitAnalysers/Source/ZXSpectrum/Viewers/SpectrumViewer.cpp:78`). IM2 support relies on a hard-coded `cpu.step == 1490` data-latch hack (`8BitAnalysers/Source/ZXSpectrum/ZXChipsImpl.c:85-86`).
- **IO Analyser core is a stub.** `FIOAnalyser::RegisterIORead/Write` bodies are commented out (`8BitAnalysers/Source/Shared/CodeAnalyser/IOAnalyser.cpp:31-43`); only the per-device access-location sets and the AY state view work. The older `IOAnalysis.cpp` is `#if 0` (`8BitAnalysers/Source/ZXSpectrum/IOAnalysis.cpp:1`).
- **Legacy/dead code.** Memory access handlers compute stats and a `bBreak` trap id that `OnInstructionExecuted` ignores; their UI is not drawn (`8BitAnalysers/Source/ZXSpectrum/MemoryHandlers.cpp` `MemoryHandlerTrapFunction`, `8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:226`, `:2046`). Machine-state captures are compiled out (`:61`). The 5 machine snapshot slots have no UI callers (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.h:147-159`). Step IO read/write buttons are commented out (`8BitAnalysers/Source/Shared/CodeAnalyser/Debugger.cpp:1519-1524`).
- **Reference caps.** 32 referrers per tracker with silent round-robin overwrite (`8BitAnalysers/Source/Shared/CodeAnalyser/CodeAnalyserTypes.h:260-265`); busy routines (e.g. a sprite plotter hit from many call sites) lose older referrers.
- **Cost.** All analysis runs in the per-tick callback (`8BitAnalysers/Source/ZXSpectrum/SpectrumEmu.cpp:469-473`) with vector searches per access; each 1 KiB page stores 1024 full `FDataInfo` objects (two reference vectors each) — memory- and CPU-heavy by design *(inferred)*.
- **No expression evaluator, no text monitor, no remote debug protocol, no trace export**, and only 48K/128K models (no +2A/+3, Pentagon, TR-DOS).
