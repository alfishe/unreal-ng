# vAmiga debugger — capability survey

**Source:** https://github.com/dirkwhoffmann/vAmiga · local checkout commit `3a0b8b4` (2026-06-10); wiki https://github.com/dirkwhoffmann/vAmiga.wiki commit `6126cd9` (2025-02-02) · C++20 core (`vAmiga/Core`), Objective-C++ bridge (`vAmiga/ObjCProxy`), Swift / Cocoa GUI (`vAmiga/GUI`, macOS only)
**Surveyed:** 2026-09-28 (source reading; the wiki and the in-repo Sphinx manual `vAmiga/Manual` used as secondary sources)
**Scope note:** Four debugging surfaces share one core API: (1) a tabbed Cocoa "Inspector" window (CPU, Memory, Agnus, Copper, Blitter, Denise, Paula, CIA, Ports, Events, Bus), (2) the "DMA debugger" that paints per-cycle bus ownership over the emulator texture, plus a per-line "logic analyzer" view, (3) RetroShell, a text console with Commander / Debugger / Navigator consoles, scripting (`source`) and a command tree, (4) remote servers (RetroShell over TCP, JSON-RPC, a GDB stub, a Prometheus exporter, serial). No rewind or time travel; only snapshots.

Paths below are relative to the parent of both checkouts: `vAmiga/...` is the emulator repo, `vAmiga.wiki/...` is the wiki.

## 2. Architecture: tracking mode and inspection

- **Tracking ("debug mode").** `Thread::trackOn(source)` keeps a 7-bit source mask and calls `_trackOn()` only on the 0->1 transition (`vAmiga/Core/Infrastructure/Thread.cpp:312-336`). Opening an Inspector window calls `emu.trackOn()` (`vAmiga/GUI/Inspector/Inspector.swift:684`); entering the RetroShell debugger console calls `trackOn(1)` (`vAmiga/Core/Misc/RetroShell/DebuggerConsole.cpp:47-56`). Closing the last inspector turns it off (`vAmiga/GUI/Inspector/Inspector.swift:902-907`).
- Tracking enables: CPU instruction logging (`vAmiga/Core/Components/CPU/CPU.cpp:646-657`), Copper list boundary tracking (`vAmiga/Core/Components/Agnus/Copper/Copper.cpp:34`, `:43`), sprite recording (`vAmiga/Core/Components/Denise/Denise.cpp:716`; `vAmiga/Core/Components/Denise/DeniseDebugger.cpp:183`). Without tracking the Copper dump prints "No recorded data. Debug mode is off." (`vAmiga/Core/Components/Agnus/Copper/CopperDebugger.cpp:70-73`). So the expensive recorders cost nothing unless a debugger view is open.
- **Auto-inspection.** A tertiary event slot `SLOT_INS` fires periodically; its data word is a bit mask of component classes; each set bit calls `info.record()` (and `metrics.record()`) on that component, which snapshots state under a lock (`vAmiga/Core/Components/Agnus/AgnusEvents.cpp:777-826`). The interval is `inspectionInterval * 28000007` master cycles (`:825`). The GUI sets the mask to all ones while an inspector is open (`vAmiga/GUI/Inspector/Inspector.swift:685`). Snapshots use `utl::Backed<T>`: `current()` reads live, `backed()` returns a lazily cached, synchronized snapshot (`vAmiga/Core/utlib/include/utl/wrappers/Backed.h:14-90`). This gives the GUI thread consistent data without stopping the emulator thread.
- **GUI cadence.** Inspectors and dashboards refresh every 5th host frame (`vAmiga/GUI/MyController.swift:294-305`); some tables refresh on every 4th call (`vAmiga/GUI/Inspector/CopperTableView.swift:98`); the logic view every 2nd (`vAmiga/GUI/Inspector/BusPanel.swift:149`).
- **Stop reasons.** All debug stops are bits in `Amiga::flags` (`RL::SOFTSTOP_REACHED`, `EOL_REACHED`, `EOF_REACHED`, `BREAKPOINT_REACHED`, `WATCHPOINT_REACHED`, `CATCHPOINT_REACHED`, `SWTRAP_REACHED`, `BEAMTRAP_REACHED`, `COPPERBP_REACHED`, `COPPERWP_REACHED`, plus snapshot and sync bits) (`vAmiga/Core/Components/AmigaTypes.h:372-388`). `Amiga::computeFrame` runs `cpu.execute()` in a loop and inspects `flags` only when non-zero (`vAmiga/Core/Components/Amiga.cpp:992-1100`); each set bit posts a message (with PC / vector) and pauses by throwing `StateChangeException`. One flag word check per CPU instruction is the only always-on cost. Consequence: every stop, including beamtraps and EOL traps raised from inside Agnus, takes effect at the next CPU instruction boundary *(inferred from the loop structure)*.

## 3. DMA debugger (bus visualization)

### 3.1 Recording bus usage per cycle

- The data source is not a debug-only structure. Agnus keeps three per-line arrays indexed by the horizontal DMA-cycle counter: `BusOwner busOwner[HPOS_CNT]`, `u32 busAddr[HPOS_CNT]`, `u16 busData[HPOS_CNT]` (`vAmiga/Core/Components/Agnus/Agnus.h:171-178`). `HPOS_CNT` is 227 (PAL; 228 for NTSC long lines) (`vAmiga/Core/Infrastructure/Constants.h:48-81`).
- `busOwner` is the arbitration table itself. `busIsFree<owner>()` returns false if `busOwner[pos.h] != NONE` (`vAmiga/Core/Components/Agnus/AgnusDma.cpp:21-25`); the Copper marks cycle E0/E1 as `BLOCKED` (`:27-38`); the Blitter yields to the CPU when BLS is set (`:44-50`). The CPU waits in `executeUntilBusIsFree()`, stepping Agnus one DMA cycle at a time, raising BLS after 2 lost cycles, adding the delay as CPU wait states, and finally writing `busOwner[pos.h] = CPU` (`vAmiga/Core/Components/Agnus/Agnus.cpp:339-371`). Recording therefore costs nothing extra: the debugger reads what arbitration already wrote.
- Each DMA routine writes owner, address and data for the current cycle and bumps a per-owner usage counter: disk (`AgnusDma.cpp:89-92`, `:182-185`), audio channel n (`:101-108`), bitplane n (`:118-125`), sprite n (`:135-142`), Copper read/write (`:153-156`, `:195-198`), Blitter (`:165-172`) (all `vAmiga/Core/Components/Agnus/AgnusDma.cpp`). CPU Chip/Slow RAM accesses fill `busAddr`/`busData` after the arbitration wait (e.g. `vAmiga/Core/Components/Memory/Memory.cpp:1080-1106`, `:1125`, `:1262`, `:1641-1794`). Refresh slots are written by the `DAS_REFRESH` event at cycles $01, $03, $05 and $E2/$E3 (`vAmiga/Core/Components/Agnus/AgnusEvents.cpp:586-607`). Sprite slots that DMA could not use are marked `BLOCKED` (`vAmiga/Core/Components/Agnus/Agnus.cpp:560-596`).
- Owners: `NONE, CPU, REFRESH, DISK, AUD0-3, BPL1-6, SPRITE0-7, COPPER, BLITTER, BLOCKED` (25 values, `i8`) (`vAmiga/Core/Components/Agnus/BusTypes.h:16-45`).
- At end of line, `Agnus::eolHandler` first calls `dmaDebugger.eolHandler()` and afterwards clears `busOwner` to `NONE` for the next line (`vAmiga/Core/Components/Agnus/Agnus.cpp:683-720`). The debugger `memcpy`s the three arrays into its own copies and records `pixel0` only when enabled (`vAmiga/Core/Components/Agnus/DmaDebugger/DmaDebugger.cpp:333-349`).

### 3.2 Channels, colors, configuration

- User-facing channel groups (`DmaChannel`): COPPER, BLITTER, DISK, AUDIO, SPRITE, BITPLANE, CPU, REFRESH (`vAmiga/Core/Components/Agnus/DmaDebugger/DmaDebuggerTypes.h:54-104`). Each group maps to one or more `BusOwner` values through a `visualize[BUS_COUNT]` bool table (audio -> AUD0..3, sprite -> SPRITE0..7, bitplane -> BPL1..6) (`vAmiga/Core/Components/Agnus/DmaDebugger/DmaDebugger.cpp:152-213`). `NONE` and `BLOCKED` are never visualized on the texture.
- Config: `enabled`, `visualize[8]`, `debugColor[8]` (RGBA as `u32`), `displayMode`, `opacity` (`DmaDebuggerTypes.h:111-128`). All are ordinary options (`Opt::DMA_DEBUG_ENABLE/MODE/OPACITY/CHANNEL0-7/COLOR0-7`, `vAmiga/Core/Infrastructure/OptionTypes.h:86-104`), so they are settable from the GUI, RetroShell (`dmadebugger set ...`, `dmadebugger open/close`, `vAmiga/Core/Misc/RetroShell/CommanderConsole.cpp:992-1017`) and RPC alike.
- Defaults (`vAmiga/Core/Infrastructure/Defaults.cpp:95-113`): disabled, mode FG_LAYER, opacity 50; all channels on except CPU. Colors (0xRRGGBBAA): Copper `FFFF00` yellow, Blitter `FFCC00` amber, Disk `00FF00` green, Audio `FF00FF` magenta, Sprite `0088FF` blue, Bitplane `00FFFF` cyan, CPU `FFFFFF` white, Refresh `FF0000` red.
- `setColor` precomputes four variants per owner: `shade(0.3)`, `shade(0.1)`, `tint(0.1)`, `tint(0.3)` (darker to lighter) (`DmaDebugger.cpp:320-331`; `shade`/`tint` mix toward black/white, `vAmiga/Core/Components/Denise/Colors.h:51-52`).

### 3.3 Drawing the overlay

- Texture geometry: `HPIXELS = 912 = 4 * HPOS_CNT`, i.e. 4 texels (hi-res pixels) per DMA cycle (`vAmiga/Core/Infrastructure/Constants.h:90`).
- Draw point: `Agnus::hsyncHandler` runs at `h == 0x12` (first HBLANK cycle), draws the *previous* line via Denise and then `dmaDebugger.hsyncHandler(vPrev)` (`vAmiga/Core/Components/Agnus/Agnus.cpp:753-767`). The debugger paints two chunks into the working frame buffer row: cycles `HBLANK_MIN..HPOS_MAX` of the previous line from its EOL copy, then cycles `0..HBLANK_MIN-1` of the current line from the live Agnus arrays at offset `pos.pixel(0)` (`DmaDebugger.cpp:351-366`). The texture row thus starts at HBLANK, matching the rendered pixels.
- `computeOverlay` per cycle (`DmaDebugger.cpp:368-437`):
  - Weights by mode, with `opacity = config.opacity / 100`: FG_LAYER: bg untouched, fg mixed with the underlying pixel at `1 - opacity`; BG_LAYER: fg drawn solid, non-visualized cycles darkened with `shade(1 - opacity)`; ODD_EVEN_LAYERS ("Mixed layers"): bg shaded by `opacity`, fg mixed at `1 - opacity`.
  - Cycles whose owner is not visualized: only the optional background darkening.
  - Visualized cycles: each of the 4 texels gets one of the 4 color variants selected by 2 bits of the recorded data word, bits 15-14, 11-10, 7-6, 3-2 (`:419-422`). The overlay therefore carries a texture that reflects the transferred data, not just a flat block per cycle.
- `vSyncHandler` clears the VBLANK rows of the next frame to `Texture::vblank` so stale overlay does not linger (`DmaDebugger.cpp:439-455`; called from `vAmiga/Core/Components/Denise/PixelEngine.cpp:251`).
- The GUI shows the *entire* texture including blanking areas while the DMA debugger is on (`vAmiga/GUI/Metal/TextureRect.swift:125-132`) and zooms out on the `DMA_DEBUG` message (`vAmiga/GUI/MyController.swift:449-450`), so refresh and HBLANK slots become visible.
- GUI controls live in the Inspector "Bus" tab: enable switch, per-channel check boxes and color wells, display-mode popup, opacity slider (`vAmiga/GUI/Inspector/BusPanel.swift:151-190`, `:287-345`). The manual describes the same controls in a "Monitor" settings panel and a Rink a Dink screenshot where the moving bitplane window is visible in the overlay (`vAmiga/Manual/Tutorials/Exploring.md:108-114`).
- The DMA debugger is a `SubComponent` with an empty serializer (`DmaDebugger.h:116`), so its state is not part of snapshots and the run-ahead instance does not share it.

### 3.4 Logic analyzer ("Bus" tab)

- Core: 4 probe channels, each `NONE`, `MEMORY` (16-bit word at an address) or `IPL` (CPU interrupt priority lines) (`vAmiga/Core/Misc/LogicAnalyzer/LogicAnalyzerTypes.h:19-60`). Samples go to `isize record[4][HPOS_CNT]` (`vAmiga/Core/Misc/LogicAnalyzer/LogicAnalyzer.h:51-52`); -1 means "no data" (`LogicAnalyzer.cpp:133-134`).
- Recording is gated by the `EVFL::PROBE` bit in Agnus' `syncEvent`, set only when a probe is connected (`vAmiga/Core/Misc/LogicAnalyzer/LogicAnalyzer.cpp:140-150`), and runs inside the REG slot handler (`vAmiga/Core/Components/Agnus/AgnusEvents.cpp:319`). Memory probes use side-effect-free `spypeek16`. Signals updated by a later event in the same cycle (IPL) are recorded with the previous cycle's timestamp (`recordCurrent` vs `recordDelayed`), and the pending half-sample is completed on pause (`LogicAnalyzer.cpp:21-25`, `:152-218`; rationale in the comment at `:158-178`). Run-ahead instances do not record (`:156`).
- GUI `LogicView`: 228 segments x 6 signals: address bus (24-bit), data bus (16-bit), probes 0-3 (`vAmiga/GUI/Inspector/LogicView.swift:13-37`). Header row: cycle number and a colored bar + label per owner (`CPU`, `REF`, `DSK`, `AUD0-3`, `BPL1-6`, `SPR0-7`, `COP`, `BLT`, `BLK` in red) using the DMA debugger colors (`:83-119`, `:181-205`). Buses are drawn only for cycles with an owner and only up to the current hpos (`:83`). Multi-bit signals use the hexagon "bus" glyph that closes when the value changes; 1-bit signals are square waves (`:287-376`). Address labels can be symbolic (region or custom register name) (`:238-241`). Zoom 1-21x, "scroll to hpos" animation (`vAmiga/GUI/Inspector/BusPanel.swift:13-20`, `:192-200`, `:219-232`). Probe presets: DMACONR, VPOSR, VHPOSR, DSKDATR, JOY0DAT, JOY1DAT, CLXDAT, ADKCONR, POT0DAT, POT1DAT, POTGOR, SERDATR, DSKBYTR, INTENAR, INTREQR, DENISEID, IPL, or any typed hex address (`BusPanel.swift:22-84`).

### 3.5 Metrics built on the same counters

- `stats.usage[owner]` accumulates per frame; `updateStats()` at EOF folds it into `copperActivity`, `blitterActivity`, `diskActivity`, `audioActivity`, `spriteActivity`, `bitplaneActivity` with an exponential moving average (w = 0.5) and zeroes the counters (`vAmiga/Core/Components/Agnus/AgnusInfo.cpp:689-728`; `vAmiga/Core/Components/Agnus/Agnus.cpp:748-749`).
- Consumers: Dashboard graphs per DMA channel, Chip/Slow/Fast/ROM read and write counts, CIA activity, audio buffer fill level and waveforms (`vAmiga/GUI/Dashboard/DashboardViewController.swift:185-203`, `:247-293`), and Prometheus gauges `vamiga_activity_*`, `vamiga_mem_accesses`, `vamiga_cia_idle_*` (`vAmiga/Core/Misc/RemoteServers/PromServer.cpp:57-130`).

## 4. Breakpoints, watchpoints, catchpoints, beamtraps

### 4.1 Data structures

- `moira::Guard { u32 addr; bool enabled = true; long ignore = 0; }` (`vAmiga/Core/Components/CPU/Moira/MoiraDebugger.h:21-36`). `Guard::eval(addr, S)` hits when `this->addr` lies in `[addr, addr + S)` and the guard is enabled; a non-zero ignore count is decremented instead of hitting (`vAmiga/Core/Components/CPU/Moira/MoiraDebugger.cpp:23-32`). So a watchpoint on one byte catches word and long accesses that cover it.
- `moira::Guards` is a plain array with doubling capacity, linear lookup, first-hit wins, and a copy of the last hit in `std::optional<Guard> hit` (`MoiraDebugger.h:43-132`; `MoiraDebugger.cpp:45-185`). Subclasses `Breakpoints`, `Watchpoints`, `Catchpoints` override `setNeedsCheck` to set or clear `CHECK_BP`, `CHECK_WP`, `CHECK_CP` bits in the CPU's `flags` word (`MoiraDebugger.cpp:187-215`; bits in `vAmiga/Core/Components/CPU/Moira/MoiraTypes.h:399-417`).
- `vamiga::GuardList` wraps a `moira::Guards` so the same guard machinery is reused by non-CPU components: "breakpoints, watchpoints, catchpoints, beamtraps, and similar constructs" (`vAmiga/Core/Infrastructure/GuardList.h:17-23`). Every mutation posts `Msg::GUARD_UPDATED` and recomputes `needsCheck` = "any guard enabled", passed to a virtual `setNeedsCheck` (`vAmiga/Core/Infrastructure/GuardList.cpp:46-171`). The CPU uses three `GuardList`s bound to Moira's lists (`vAmiga/Core/Components/CPU/CPU.h:53-55`); the Copper has `CopperBreakpoints`/`CopperWatchpoints` that set `copper.checkForBreakpoints/Watchpoints` (`vAmiga/Core/Components/Agnus/Copper/CopperDebugger.cpp:18-38`); beamtraps subclass it too (below).
- Info exported to the GUI: `GuardInfo { addr, enabled, ignore }` (`vAmiga/Core/Infrastructure/GuardListTypes.h:20-26`).

### 4.2 Keeping checks cheap

- Breakpoints: checked after each instruction only if `flags & CHECK_BP` (`vAmiga/Core/Components/CPU/Moira/Moira.cpp:343-354`); the same bit also carries single-step, because `stepInto` sets `softStop = -1` and `stepOver` sets `softStop = PC + instruction length`, then forces `CHECK_BP` on (`MoiraDebugger.cpp:251-277`). A soft stop deletes itself when reached and restores `CHECK_BP` to "list non-empty".
- Watchpoints: one flag test in the memory read/write dataflow path (`vAmiga/Core/Components/CPU/Moira/MoiraDataflow_cpp.h:377-379`, `:430-432`).
- Catchpoints: evaluated only when an exception vector is taken (`MoiraDataflow_cpp.h:689`), so no per-instruction cost.
- Instruction logging: `flags & LOGGING` per instruction (`Moira.cpp:319-322`).
- Copper: `checkForBreakpoints && breakpoints.eval(coppc)` on each Copper fetch, `checkForWatchpoints && watchpoints.eval(reg)` after each MOVE (`vAmiga/Core/Components/Agnus/Copper/CopperEvents.cpp:107-110`, `:167-170`).
- Beamtraps: zero per-cycle cost. `Beamtraps::scheduleNextEvent()` computes the distance from the current beam position to each trap `(v,h)` (packed as `HI_W_LO_W(v,h)` in the guard address) and schedules a single `BTR_TRIGGER` event in `SLOT_BTR` for the nearest one; servicing the event sets `BEAMTRAP_REACHED` and reschedules (`vAmiga/Core/Components/Agnus/DmaDebugger/Beamtraps.cpp:22-56`; dispatch `vAmiga/Core/Components/Agnus/Agnus.cpp:525-526`).
- EOL / EOF traps: one-shot bools tested in the existing end-of-line / end-of-frame handlers (`DmaDebugger.cpp:336-337`, `:460-461`).

### 4.3 Kinds and keying

- CPU breakpoint: 24-bit logical PC; odd addresses rejected (`vAmiga/Core/Misc/RetroShell/DebuggerConsole.cpp:218-232`). No bank qualification (the Amiga has a flat address space). GDB `Z0`/`z0` map to the same list; other Z types are acknowledged but ignored (`vAmiga/Core/Misc/RemoteServers/GdbServerCmds.cpp:360-402`).
- CPU watchpoint: address, any access size, reads and writes alike (no R/W distinction in the guard) (`DebuggerConsole.cpp:271-285`).
- Catchpoint: vector number 0-255; `catch interrupt n` = vector n+24 (n 1..7), `catch trap n` = vector n+32 (n 0..15) (`DebuggerConsole.cpp:323-370`).
- Software trap: `SoftwareTraps::create(instr)` picks the next free LINE-A opcode from $A000, stores the original opcode in a map (max 512) (`vAmiga/Core/Components/CPU/Moira/MoiraDebugger.cpp:217-242`); the executor stops and later executes the original (`vAmiga/Core/Components/CPU/Moira/MoiraExec_cpp.h:38-48`); the disassembler substitutes the original so the listing stays clean (`vAmiga/Core/Components/CPU/CPU.cpp:83-91`). `FloppyDrive::catchFile(path)` mounts the disk's file system, patches the first code-hunk word of the named executable with a trap, and swaps the modified disk in (`vAmiga/Core/Peripherals/Drive/FloppyDrive.cpp:1151-1190`).
- Copper breakpoint: Copper list address (`cbreak at`); Copper watchpoint: custom register offset (`cwatch at`, although the help text says "Memory address") (`DebuggerConsole.cpp:409-423`, `:463-477`).
- Beamtrap: `btrap at x=<h> y=<v> [ignores]` (`DebuggerConsole.cpp:516-532`); listing shows `(v,h)` and "(Disabled for N hits)" (`DmaDebugger.cpp:22-41`).
- OS-level: the diagnostic board's ROM reports `AddTask`/`RemTask`/`LoadSeg` to the emulator (`vAmiga/Core/Components/Zorro/DiagBoard.cpp:165-182`); `os catch <name>` pauses when a matching task is added; the GDB server uses the same hook to wait for a process (`vAmiga.wiki/GDB-Server.md`, "server gdb attach file").

### 4.4 GUI

- Guard tables (`BreakTableView`, `WatchTableView`, `CopperBreakTableView`): enable toggle column, editable address column (edit calls `replace`, i.e. move), delete column (`vAmiga/GUI/Inspector/GuardTableView.swift:11-344`).
- On `BREAKPOINT_REACHED` / `WATCHPOINT_REACHED` / `CATCHPOINT_REACHED` / `SWTRAP_REACHED` the inspector scrolls the disassembly to PC and highlights it (`alertAddr`); Copper and beam stops trigger a full refresh (`vAmiga/GUI/Inspector/Inspector.swift:803-835`).

## 5. RetroShell

- Three consoles cycled with `.` / `..`: Commander (configuration, media, input injection, servers), Debugger, and a file-system Navigator (`vAmiga/Core/Misc/RetroShell/RetroShell.h:71-91`; `vAmiga/Core/Misc/RetroShell/DebuggerConsole.cpp:85-113`). Rendered as an overlay layer over the emulator window (`vAmiga/GUI/Layers/Console.swift:14`).
- Command registration is declarative: `root.add({ .tokens, .ghelp, .chelp, .flags, .args, .func, .payload })`; argument specs support optional (`rs::opt`), `key=value` (`rs::keyval`), hidden; `root.clone({"m"}, "m.w", {2})` creates size variants through the payload vector (`DebuggerConsole.cpp:596-611`). Help groups via `RSCommand::currentGroup` (`:118`, `:561`).
- `registerComponent(c)` auto-generates `<component>` (show config) and `<component> set <OPTION> <value|enum>` for every option of every component from its option list and enum reflection (`vAmiga/Core/Misc/RetroShell/Console.cpp:1047-1147`). That is how `dmadebugger set ...` and `logicanalyzer set ...` exist without hand-written commands.
- Debugger prompt: `(v,h) $PC: ` (`DebuggerConsole.cpp:29-44`). On pause the console prints `state`: last 8 trace entries, the status summary line, next 8 instructions (`DebuggerConsole.cpp:19-27`; `vAmiga/Core/Components/Amiga.cpp:784-795`). Pressing Return with an empty line in a paused debugger steps one instruction (`DebuggerConsole.cpp:67-83`).
- Command inventory (debugger console): `p[ause]`, `g[oto]`, `s[tep]`, `n[ext]`, `eol`, `eof`; `break|watch|catch|cbreak|cwatch|btrap` each with `at/delete/toggle`; `d`, `a`, `m`, `w`, `c`, `f`, `e`; `r <chip>`; `? <component> [...]` including `? agnus beam|dma|sequencer|events`, `? copper list 1|2`, `? paula audio filter`, `? cia tod`, `? server gdb`; `os ...`; `checksums`; `debug [channel level]`; `%` (`DebuggerConsole.cpp:120-1627`).
- Line editing: history buffer, first TAB auto-completes, repeated TAB shows help for the typed prefix (`vAmiga/Core/Misc/RetroShell/Console.cpp:279-364`).
- Scripts: `source <file>` runs a script asynchronously; `wait <sec>` schedules an `RSH_WAKEUP` event and suspends the script by throwing `ScriptInterruption` (`Console.cpp:1002-1032`). Commands execute on the emulator thread via the command queue (`Cmd::RSH_EXECUTE`, `vAmiga/Core/Components/Amiga.cpp:966-969`).

## 6. Copper debugger

- List tracking: on every Copper jump (COP1LC/COP2LC load) `jumped()` looks up or creates a `CopperList{start,end}` in an address-keyed cache; on every PC advance `advanced()` extends `end` (`vAmiga/Core/Components/Agnus/Copper/CopperDebugger.cpp:146-204`). Only active while tracking. The GUI list view uses these bounds (capped at 500 rows), marks illegal instructions, and follows `coppc0` (`vAmiga/GUI/Inspector/CopperTableView.swift:55-120`).
- Disassembly format: `$addr: $w1 $w2    MOVE $0FFF, COLOR00` / `WAIT ($2C,$07)` / `WAITb ($80,$01), ($FE,$7F)` (mask printed only when not $FF/$FF) (`CopperDebugger.cpp:206-273`).
- Copper checksums (`COP_CHECKSUM` channel) FNV-hash every fetched instruction word for regression comparison (`vAmiga/Core/Components/Agnus/Copper/CopperEvents.cpp:116-120`, `:136-137`).

## 7. Event scheduler inspector

- Slots: primary REG, CIAA, CIAB, BPL, DAS, COP, BLT, SEC; secondary CH0-3, DSK, VBL, IRQ, IPL, KBD, TXD, RXD, POT, TER; tertiary DC0-3, HD0-3, MSE1-2, SNP, RSH, KEY, SRV, SER, BTR (beamtraps), ALA (GUI alarms), INS (inspection) (`vAmiga/Core/Components/Agnus/AgnusTypes.h:75-127`). Secondary/tertiary slots are only scanned when SEC/TER wake-up events are due (`vAmiga/Manual/Developer/EventScheduler.md`).
- GUI "Events" tab columns: slot, event name, trigger cycle ("none" when idle, grayed), frame ("previous"/"current"/"current + n"), vpos, hpos, remark ("due immediately" / "due in N DMA cycles", master cycles / 8) (`vAmiga/GUI/Inspector/EventTableView.swift:38-100`). Text version: `? agnus events` (`vAmiga/Core/Components/Agnus/AgnusInfo.cpp:567-605`).
- `? agnus dma` prints the sequencer's per-cycle tables `bplEvent[i]` + `dasEvent[i]` and the `nextBplEvent`/`nextDasEvent` links, two columns per row (`vAmiga/Core/Components/Agnus/Sequencer/SequencerInfo.cpp:23-46`). This is the precomputed "what happens in each slot of this line" table that drives DMA.

## 8. Logging

- Every channel is a `constexpr long` in `utl::debug` (0 = off, non-zero = on or a parameter, e.g. `LINE_DEBUG` holds the line number) (`vAmiga/Core/debug.h:12-90`). `debug.cpp` registers each as a runtime `LogChannel` via `Loggable::subscribe(name, level, description)`, level 7 if the constant is non-zero, otherwise disabled (`vAmiga/Core/debug.cpp:16-22`, channel list `:24-160`). Examples: `DMA_DEBUG` "DMA registers", `DDF_DEBUG`, `SEQ_DEBUG`, `COP_DEBUG`, `BLTTIM_DEBUG`, `SPR_DEBUG`, `INT_DEBUG`, `CIA_DEBUG`, `DSK_DEBUG`, `AUD_DEBUG`, `GDB_DEBUG`, plus behavioral switches such as `SEQ_ON_STEROIDS` ("Disable sequencer fast-paths"), `BLT_MEM_GUARD`, `ALIGN_HEAD` ("Make head movement deterministic").
- Release builds (`NDEBUG`): `logMsg` expands to `if constexpr (debug::key) log(...)`, so disabled channels compile to nothing; debug builds always call `log()` and filter at run time (`vAmiga/Core/debug.h:345-367`). Header comment states the same policy (`:193-201`). Levels follow syslog 0-7 (`vAmiga/Core/utlib/include/utl/abilities/Loggable.h:34-45`). RetroShell `debug <channel> <level>` exists only when `debugBuild` (`vAmiga/Core/Misc/RetroShell/DebuggerConsole.cpp:1586-1606`); `debug` without arguments lists all variables (`:1571-1583`).
- Prefix: for LOG_DEBUG messages the Amiga object prepends run-ahead marker, `[frame] (v,h)`, CPU PC, Copper PC when the Copper is servicing, IPL, DMACON letters, INTENA and INTREQ (verbosity 5, compile-time) (`vAmiga/Core/Components/Amiga.cpp:93-140`). Sample: `[1234] ( 44,112) 00FC0F2A [000420] 00 BCB-D- 602C 0020 pokeDMACON(8200)` *(format reconstructed from the code, not captured)*.
- Remote servers echo traffic into RetroShell when `verbose` is on (`vAmiga/Core/Misc/RemoteServers/RpcServer.cpp:44-72`).

## 9. Remote debugging, automation, persistence

- `RemoteManager` owns five servers, each with `enable/port/protocol/verbose` options (`vAmiga/Core/Misc/RemoteServers/RemoteServer.h:51-54`); polled from the `SLOT_SRV` event (`vAmiga/Core/Components/Agnus/AgnusTypes.h:116`).
- JSON-RPC: request `{"method":"retroshell","params":"<command>","id":n}`; the command runs through RetroShell and the captured console output becomes `result`; errors map to JSON-RPC codes (CoreError fault ids, -32000 for parse errors) (`vAmiga/Core/Misc/RemoteServers/RpcServer.cpp:62-178`). So every shell command is an RPC endpoint.
- GDB: packets `v q Q g s n H G ? ! k m M p P c D Z z` (`vAmiga/Core/Misc/RemoteServers/GdbServerCmds.cpp:455-475`); stop reply `T05`; `qOffsets` reports Text/Data/Bss from the attached process' segment list (`:47-56`); starting the server pauses the emulator (`vAmiga/Core/Misc/RemoteServers/GdbServer.cpp:97-100`). The wiki calls it a proof of concept (`vAmiga.wiki/GDB-Server.md`).
- Prometheus: text exposition of host load, FPS, DMA activity, CIA idle, memory accesses (`vAmiga/Core/Misc/RemoteServers/PromServer.cpp:29-130`).
- Snapshots: `takeSnapshot(compressor, delay, repeat)` either returns a snapshot or schedules `SNP_TAKE` in `SLOT_SNP`, repeating every `delay` seconds; the snapshot travels to the GUI in a message (`vAmiga/Core/Components/Amiga.cpp:1146-1188`). No history ring or reverse execution in the core. Run-ahead keeps a second emulator instance that is fast-forwarded N frames (`vAmiga/Core/Infrastructure/Emulator.cpp:341-358`); debug recorders skip it (`LogicAnalyzer.cpp:156`).
- Regression support: `regression setup <scheme>` / `regression run`, texture dump of a fixed crop for image diffing (`vAmiga/Core/Misc/RegressionTester/RegressionTester.h:27-46`), `checksums` command (`DebuggerConsole.cpp:1561-1569`).

## 10. Notable and unique ideas

Ranked by value for a ZX Spectrum ULA-beam and contention debugger.

1. **Per-cycle bus-owner array that is also the arbitration table.** `busOwner[h]` decides who gets the bus and is also what the debugger draws. For the Spectrum: a per-line `owner[t]` array (ULA fetch, CPU contended access, CPU uncontended, IO, floating bus read) filled by the contention logic itself gives an exact, free contention recorder. Contention and the view cannot drift apart.
2. **DMA overlay drawn at HSYNC into the same frame buffer row.** Painting the overlay one line late from a copied array, and showing the full texture including borders and blanking, lines up bus activity with beam pixels. A ZX version: color each T-state group (e.g. 2 pixels per T-state) by owner over the screen and border, with opacity and three blend modes (on top of the image, darken the rest, or both).
3. **Data-dependent shading inside a slot.** Picking one of four shades from 2-bit groups of the transferred data gives a visible texture that shows what was fetched, not only who fetched. Cheap trick for showing ULA bitmap/attribute fetch contents or CPU data over contended cycles.
4. **Logic-analyzer timing diagram for one raster line.** Owner label per cycle, address bus, data bus, and user probes (any memory word, IPL) drawn as a waveform with symbolic addresses. A Spectrum equivalent: per-T-state row of the current line with MREQ/IORQ, address, data, INT, and probes such as port $FE or the floating bus value. The recordCurrent/recordDelayed split is a useful lesson in sampling signals at the right point of the cycle.
5. **Beamtraps as scheduled events.** A raster breakpoint `(v,h)` is one event on the scheduler, costing nothing per cycle. Direct fit for "stop at line L, T-state T" on the Spectrum and for "finish line" / "finish frame" stepping (the `eol` / `eof` one-shot traps).
6. **Beam-stamped logs.** Every debug line carries `[frame] (v,h) PC` plus chip state letters. For contention and ULA work, logging `frame:line:tstate` on every message makes traces comparable with raster diagrams and with other emulators.
7. **One guard class for every kind of trap.** Address, vector, Copper PC, register number and beam coordinate all reuse `{addr, enabled, ignore}` with a "needs check" callback that flips a single flag bit in the hot loop. Keeps checks cheap and gives uniform CLI and GUI tables.
8. **Tracking mode with a source bitmask.** Expensive recorders (trace ring, Copper list bounds, sprite capture) run only while a debugger view is open, reference-counted per source. Plus a periodic, mask-driven snapshot event (`SLOT_INS`) that copies component state for the GUI without stopping emulation.
9. **Per-cycle slot table dump.** `? agnus dma` prints the precomputed per-line event table. A Spectrum analogue is dumping the contention delay table for the current model and line so users can check the pattern (6,5,4,3,2,1,0,0).
10. **Everything is an option, every command is RPC.** Debugger overlays are ordinary options, so shell, GUI and JSON-RPC set them the same way; `registerComponent` generates `set` commands from option metadata. Similar to our WebAPI/MCP parity goal.
11. **Software traps via unused opcodes, and OS-aware catch.** Patching the first instruction of a file on disk to stop at program entry, and a diagnostic board that reports task creation. Spectrum analogues: stop on `LOAD` completion or at a TR-DOS file's start address.

## 11. Gaps and caveats

- **Buffer overflow in the DMA debugger copy.** `DmaDebugger::busAddr` is `u16[HPOS_CNT]` (`vAmiga/Core/Components/Agnus/DmaDebugger/DmaDebugger.h:73`) but `eolHandler` copies `sizeof(agnus.busAddr)` bytes from a `u32[HPOS_CNT]` array (`DmaDebugger.cpp:343`; `vAmiga/Core/Components/Agnus/Agnus.h:175`). The extra bytes land in the following members; `busData` is overwritten by the next `memcpy`, which probably hides it *(inferred from member order)*.
- **Blend indexing slip.** In `computeOverlay` texels 1-3 of a cycle are mixed with `ptr[2]`, `ptr[4]`, `ptr[6]` instead of `ptr[1..3]`, i.e. with pixels of the next cycle (`DmaDebugger.cpp:426-429`).
- **Beamtraps ignore enable and ignore count.** `scheduleNextEvent` walks every guard without checking `enabled` or `ignore`, and `setNeedsCheck(value)` ignores its argument (`vAmiga/Core/Components/Agnus/DmaDebugger/Beamtraps.cpp:22-56`). Disabled traps still fire *(inferred)*.
- **Beamtrap argument help is swapped.** `x` is described as "Vertical trigger position" and `y` as "Horizontal" although `x` is used as h (`vAmiga/Core/Misc/RetroShell/DebuggerConsole.cpp:521-530`).
- **Copper hit address truncated.** The Copper breakpoint/watchpoint messages cast the hit address to `u8` (`vAmiga/Core/Components/Amiga.cpp:1070-1084`).
- **Copper list 2 disassembly.** `CopperDebugger::disassemble(os, list, ...)` always passes list 1 to the symbolic formatter, and walks from `cop1lc`/`cop2lc` rather than the tracked start (`CopperDebugger.cpp:206-231`).
- **`cwatch` semantics.** Help says "Memory address", evaluation uses the register offset (`DebuggerConsole.cpp:463-477` vs `vAmiga/Core/Components/Agnus/Copper/CopperEvents.cpp:167`).
- **CPU disable does not clear the check flag.** `GuardList::update` hands `needsCheck` to the base `setNeedsCheck`, which is a no-op for the CPU lists; Moira only clears `CHECK_BP` when the list becomes empty (`vAmiga/Core/Infrastructure/GuardList.h:114`; `MoiraDebugger.cpp:96-108`). Disabled breakpoints still cost a scan *(inferred)*.
- **Trace re-disassembles current memory.** The trace view disassembles `pc0` from live memory, not the opcode that was executed; self-modifying code shows the new bytes (`vAmiga/Core/Components/CPU/CPU.cpp:689-691`).
- **Trace depth.** 256 entries, fixed (`MoiraDebugger.h:213`); no trace-to-file, no per-cycle trace.
- **No expressions or conditions.** Breakpoints have only ignore counts; arguments accept plain numbers only (`vAmiga/Core/utlib/src/io/Parser.cpp:54-86`); no symbol files.
- **No read/write split for watchpoints** and no watchpoints for custom register reads.
- **Stops land on instruction boundaries.** Beam and EOL traps are serviced after the running CPU instruction completes (`vAmiga/Core/Components/Amiga.cpp:995-1000`).
- **Bus text dump not wired.** `Category::Bus` exists (`vAmiga/Core/Components/Agnus/AgnusInfo.cpp:550-565`) but no RetroShell command references it in this checkout (grep).
- **Prometheus duplicate.** `vamiga_activity_disk` is emitted twice (`vAmiga/Core/Misc/RemoteServers/PromServer.cpp:82-88`).
- **Docs drift.** The wiki uses GDB port 8082 (`vAmiga.wiki/GDB-Server.md`); the code default is 8083 (8082 is JSON-RPC) (`vAmiga/Core/Infrastructure/Defaults.cpp:222-227`). The manual's "activity monitors" overlay appears replaced by the Dashboard window in this checkout (`vAmiga/Manual/Tutorials/Exploring.md:116-118`; `vAmiga/GUI/Dashboard/`) *(inferred)*.
- **No rewind / time travel**, no reverse step, no memory access heat map or code/data coverage.
- **GUI is macOS-only** (Cocoa/Metal); RetroShell and remote servers are the portable parts.
