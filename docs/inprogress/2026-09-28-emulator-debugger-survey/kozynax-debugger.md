# Kozynax debugger — capability survey

**Source:** https://github.com/kozynax/kozynax · local checkout commit `cd96075` (2026-09-24, merge of PR #5 `feature/adaptive_scale`; `git describe` = `v0.94-10-gcd960758`, tags `v0.94`/`v0.95` from 2026-09-12) · C# / .NET 8; SDL2 via Silk.NET (Windows/Linux/macOS) plus a WinForms build for Windows
**Surveyed:** 2026-09-28 (source reading)
**Scope note:** Kozynax is a fork of ZXMAK2 by Alexander Tsidaev (also the author of ZXMAK2's GDB stub). The emulation engine and its debug API are unchanged from ZXMAK2; the debugger work is a **port of ZXMAK2's default debugger** to a toolkit-neutral model (`DebuggerDialog`) with three front-ends: WinForms, an 8×8 character-cell UI drawn inside the SDL window, and a real ANSI terminal (`--tui`). ZXMAK2's Adlers debugger and DebuggerEx were **removed**; the GDB stub is kept byte-for-byte. The CLI (`Kozynax.Cli`) only converts disk images — no debugger automation. Shared engine behavior is described in [zxmak2-debugger.md](zxmak2-debugger.md); this document has its own full registry. Paths are relative to the repository root (`kozynax/`).

## 2. What Kozynax changed, what it kept, what it dropped

**Timeline (git).** The fork diverges from ZXMAK2 in 2022-10/11 ("Remove non-standard debuggers (Adlers and DebuggerEx) since it would be hard for now to port", `bcc62d94`/`17709a79`, 2022-11-05; "Remove log4net", `577d3105`; "Debugger rewritten as IViewImplementation", `5f81acd1`; "Extract Hex Viewer logic to separate class (DataPanelComponent)", `b8a81345`; "Make Sprinter Debugger inheritor of regular debugger", `22008dde`). The SDL backend and Kozui terminal UI land 2026-08-04..06; the SDL debugger 2026-08-11..19 ("Add basic debugger support" `c7e80381`, "Show/hide debugger with ESC (as in Unreal Speccy)" `1f91ff37`, "colorize breakpoint lines, use Space to set BP, use ctrl+g" `484c6190`, "load/save block … ctrl+L, ctrl+S" `00c7253a`, "right-click menus" `c723858d`, "Rework debugger window" `2c4f90dc`, "Sprinter debugger" `d62962f0`); CLI `convert` and `--tui` 2026-09-09/10; release tags 2026-09-12. ZXMAK2's 2023 debugger commits (status bar with frame tact, menu/toolbar, "don't update debugger when not visible") are merged in.

**Kept unchanged** (verified by diff against the ZXMAK2 checkout): `Spectrum.cs`, `VirtualMachine.cs`, `IDebuggable.cs`, `Breakpoint.cs`, `DasmTool.cs`, `TimingTool.cs`, the whole `ZXMAK2.Hardware.GdbServer` project; `EventManager.cs` differs only by the `PORTDEBUG` blocks. Consequently every engine-level property and defect described in [zxmak2-debugger.md §4.1, §5, §8, §10](zxmak2-debugger.md) applies: PC-only logical breakpoints checked per instruction after execution, skipped while HALTED; textual step-over heuristic with the 71680*50*5 T prompt; no step out; GDB stub remove-breakpoint and watch-stop bugs.

**Dropped:** Adlers debugger (command line, conditional/memory breakpoints, IL-compiled conditions, trace filters/counters, stack view, comments/notes, find bytes, save as `dis.asm`/`DEFB`, Pasmo assembler, graphics editor), DebuggerEx docking UI, log4net file logging, `ZXMAK2.Host.Media` recorders (`7166158b`). The `ZXMAK2.Hardware.Adlers` directory no longer exists.

**Added:** a single debugger model rendered by three front-ends, ESC-to-debugger, text-mode ergonomics (keyboard + mouse + context menus), a terminal (`--tui`) mode, stderr logging and Windows console attach, compile-time port logging, xUnit accuracy tests.

## 3. Debugger model and front-ends

- **Model.** `DebuggerDialog` (`kozynax/src/Kozynax.UI/DebuggerDialog.cs:23`) owns `DasmPanelComponent` (16 lines initially) and `DataPanelComponent` (8 lines × 8 columns) (`:57-66`), five Kozui `ListView<string>` controls (dasm, data, registers, flags, states) and six buttons (`:68-123`). All actions — `StepInto/StepOver/Run/Stop/ResetCpu`, `DasmGoToPC/DasmGoToAddress/DataGoToAddress`, `SetDataColumnCount`, `ClearBreakpoints`, `ToggleFlag`, `ResetCpuState`, `EditSelectedDataByte`, `LoadMemoryBlock/SaveMemoryBlock` — are public methods (`:527-909`), so any front-end is a key/mouse mapping. It raises `Breakpoint`, `UpdateState`, `CpuDetailsUpdated`, `RunningStateChanged`, `CloseRequested` (`:25-31`). Layout: title, toolbar, right side column (registers/flags/state), center dasm (fill) with hex view docked at the bottom (`:947-1046`). Backdrop capture is disabled because reading back the presented frame can hang some backends (`:18-22`).
- **WinForms.** `FormCpu` no longer holds `DasmTool`/`TimingTool`; it binds its owner-drawn panels to the model's components and copies register/flag/state lines from the model on `CpuDetailsUpdated` (`kozynax/src/ZXMAK2.Hardware.WinForms/General/FormCPU.cs:66-110`). Status bar colors and `T: n / N` are unchanged from ZXMAK2 2023 (`:91-108`).
- **SDL window.** `DebuggerToolView` implements `IDebuggerGeneralView`, hosts the model in `TerminalKozuiDialogHost<DebuggerDialog>` with a `DebuggerTerminalSession` for input, and runs it as a modal loop (`kozynax/src/ZXMAK2.Host.Sdl/Views/DebuggerToolView.cs:59-86`). The "terminal" here is an in-window 8×8-cell surface (`ITerminal`, "backend-agnostic immediate-mode overlay surface", `kozynax/src/ZXMAK2.Host/Terminal/ITerminal.cs:3-7`) drawn with the Spectrum ROM font plus Quorum Cyrillic glyphs (`TerminalFont.cs:9-13`). While the debugger is open it replaces the emulator picture *(inferred from `CaptureBackdrop = false` and the modal host loop)*.
- **Real terminal.** With `--tui` the same `ITerminal` is a `StdioTerminal`: ANSI alternate screen, hidden cursor, 24-bit `38;2`/`48;2` colors, surface reported as `cols×8 × rows×8` "so TerminalKozuiPresenter cell math is unchanged" (`kozynax/src/ZXMAK2.Host/Terminal/StdioTerminal.cs:9-13`, `:188-230`, `:277-291`, `:427-429`; selection in `kozynax/src/ZXMAK2.Host.Sdl/Program.cs:55-58`). Input comes from `Console.ReadKey` (`StdioTerminal.cs:353-359`); no mouse decoding was found in `StdioTerminal`, so mouse features apply to the SDL cell UI *(inferred)*. The SDL video window still exists in this mode; `--tui` moves UI chrome (menus, dialogs, debugger) to the console.
- **Sprinter.** `SprinterDebuggerDialog : DebuggerDialog` adds an `ExtendedVariables` list at the bottom of the side column with Sprinter MMU/port values (`kozynax/src/Kozynax.UI/SprinterDebuggerDialog.cs:13-112`) — the same data as ZXMAK2's Sprinter `DebugForm`.

## 4. Breakpoints and conditions

- Only execution breakpoints exist in the UI: `dasmPanel_SetBreakpoint` removes any breakpoint whose `Address == addr` or adds `new Breakpoint(addr)` (`kozynax/src/Kozynax.UI/DebuggerDialog.cs:509-525`); the engine predicate is `PC == addr` on the logical address (`kozynax/src/ZXMAK2.Engine/Entities/Breakpoint.cs:20-24`). No enable/disable, count, condition or action; no breakpoint list view — breakpoints are visible only as `*`/red rows in the disassembly (`DebuggerDialog.cs:334-343`, `:386-397`).
- Evaluation and cost are the ZXMAK2 engine's: zero cost when the list is empty, otherwise `List.Any(predicate)` after every instruction, skipped while HALTED (`kozynax/src/ZXMAK2.Engine/Spectrum.cs:103-123`, `:326-330`).
- The predicate-breakpoint API (`Breakpoint(label, Predicate<IMachineState>)`) and bus hooks survive, so conditional/memory breakpoints are possible programmatically, but no front-end or CLI exposes them. Memory read/write/access watchpoints are reachable only through the unchanged GDB stub (`kozynax/src/ZXMAK2.Hardware.GdbServer/GDBJtagDevice.cs:69-131`), which does not actually stop on them (see ZXMAK2 doc §10).

## 5. Execution control and entry points

- **Keys in the debugger** (text UI): F3 reset, F5 stop, F7 step into, F8 step over, F9 run (`kozynax/src/ZXMAK2.Host.Sdl/Views/DebuggerTerminalSession.cs:509-529`); Esc or window close exits (`:55-60`, `:97-102`). Dasm focus: Up/Down/PgUp/PgDn, Space/Enter toggle breakpoint; hex focus: arrows/PgUp/PgDn, Enter poke (`:150-207`). Ctrl+G goto in the focused panel (`:107-126`); Ctrl+L/Ctrl+S block I/O in hex focus (`:128-148`). WinForms keeps F3/F5/F7/F8/F9 (`kozynax/src/ZXMAK2.Hardware.WinForms/General/FormCPU.cs:168-206`).
- **F7/F8 while running now stop the CPU** (the ZXMAK2 form ignored them) (`kozynax/src/Kozynax.UI/DebuggerDialog.cs:676-716`).
- **Entering the debugger**: Esc in the bare SDL window (not fullscreen) pauses a running VM, executes the "Debugger" command (blocking), and un-pauses afterwards unless the user already resumed with F9; if the machine has no debugger device, Esc falls back to Exit (`kozynax/src/ZXMAK2.Host.Sdl/SdlMainView.cs:561-612`). A breakpoint hit while the debugger is closed opens it and arranges `DoRun()` on close (`kozynax/src/ZXMAK2.Host.Sdl/Views/DebuggerToolView.cs:99-115`, `:166-183`) — so closing the window after a breakpoint resumes emulation automatically.
- Step semantics (prefix-complete step into, heuristic step over, no step out) and the `frmT` edit (advances `CPU.Tact` to a given frame position) are inherited (`kozynax/src/Kozynax.UI/DebuggerDialog.cs:819-831`; engine: `kozynax/src/ZXMAK2.Engine/Spectrum.cs:270-324`).

## 6. Memory, device and video views

- **Hex view**: `XXXX  HH×8  chars`; ZX charset mapping of ZXMAK2 replaced by printable-ASCII-or-`.` for terminal fonts (`kozynax/src/Kozynax.UI/DebuggerDialog.cs:345-408`). Columns 1..32 via dialog (`:561-571`). Poke works while running (comment "Match WinForms", `:784-798`). All addressing is 64 KiB logical through `IDebuggable.ReadMemory` (debug page tables, no bank selector).
- **Memory map** (Kozui port): CMR0/CMR1 with Edit buttons, page mapped at each 16K window (`ROM #nn` / `RAM #nn`), DOSEN/SYSEN checkboxes, and — replacing ZXMAK2's PropertyGrid — a list of memory-device properties discovered by `[HardwareValue]`, `[HardwareSwitch]`, `[HardwareReadOnly]` attributes, formatted `> Name: #xx` / `on|off`, editable in place, refreshed every 250 ms (`kozynax/src/Kozynax.UI/MemoryMap.cs:51-75`, `:110-126`, `:279-360`).
- **WD1793 window**: live `DumpState()` text every 300 ms (`kozynax/src/Kozynax.UI/FddDebugDialog.cs:13-16`, `:53-54`).
- **Debug Info OSD** in SDL mirrors ZXMAK2's MDX OSD text fields (`kozynax/src/ZXMAK2.Host.Sdl/SdlDebugOverlay.cs:81-87`) without the frame-time graphs *(inferred: only text lines at `:81-87`)*.
- No beam position overlay, no screen/sprite viewer (Adlers graphics editor dropped), no AY/sound view.

## 7. Logging, tracing, CLI and tests

- **Logging**: `Logger` keeps ZXMAK2's static API but its `ILog` is never instantiated; extension methods on the null instance write every level to `Console.Error` as `[HH:mm:ss.fff] Debug: …` (`kozynax/src/ZXMAK2.Logging/Logger.cs:10-24`, `kozynax/src/ZXMAK2.Logging/ILogExtensions.cs:7-16`). No level filter, no file sink. On Windows `--console`/`--tui` attach a console so the output is visible (`kozynax/src/Kozynax.Cli/CommandLine.cs:23-75`).
- **Tracing** is limited to device `logIo` (e.g. WD1793 register access with PC and T, now toggled from the Beta Disk settings dialog, `kozynax/src/Kozynax.UI/BetaDiskSettings.cs:39`, `:90`) and the compile-time `PORTDEBUG` port log (`kozynax/src/ZXMAK2.Engine/EventManager.cs:259-275`). No instruction trace.
- **CLI**: `kozynax convert <input> <output>` converts disk images (e.g. TRD→HFE, SCL→UDI) headlessly with console `IUserMessage`/`IUserQuery` (`kozynax/src/Kozynax.Cli/CommandLine.cs:34-45`, `:101-145`). Everything else is host flags. No commands for loading/running/inspecting a machine.
- **Tests** (`kozynax/tests`, xUnit): the ZXMAK2 console harness's ULA contention patterns are now `[Theory]` cases — the test builds a 48K memory + ULA bus, fills RAM at `#4000` with the opcode, sets all registers to `#4000`, positions `CPU.Tact` at the first pattern tact and asserts the frame tact after each `DebugStepInto()` (`kozynax/tests/UlaContentionTests.cs:21-116`; patterns "from the legacy src/Test harness", `kozynax/tests/UlaContentionPatterns.cs:3-6`). These use the debug API (`DebugStepInto`, `DebugReadMemory`, `WRMEM_DBG`) as a headless automation surface.

## 8. Notable and unique ideas (selling points, stated precisely)

1. **Cross-platform ZXMAK2 debugger.** The ZXMAK2 default debugger (registers, flags, CPU state incl. MEMPTR/LPC/FX/XFX, dasm with T-state column, hex view, POKE, exec breakpoints, step into/over, frame-tact edit, block load/save) now runs on Linux and macOS via SDL. This is the main debugger news; the feature set is ZXMAK2-default parity, not beyond.
2. **One debugger model, three renderers** (WinForms, SDL cell UI, ANSI terminal). The model/view split (`DebuggerDialog` + panel components) is a clean pattern for keeping GUI and TUI debuggers in lockstep.
3. **Debugger in a real terminal** (`--tui`): usable over SSH-like text sessions for the UI chrome; rare among Spectrum emulators.
4. **Unreal-Speccy-style ergonomics**: Esc toggles into the debugger with pause/resume bookkeeping; breakpoint auto-opens the debugger and resumes on close; Space/Enter toggle breakpoints; Ctrl+G goto; Ctrl+L/Ctrl+S block I/O; context menus; wheel and double-click in the cell UI.
5. **ZX-ROM-font rendering** of the debugger (plus Quorum Cyrillic) with integer HiDPI scaling — the debugger looks native to the machine.
6. **Attribute-reflected hardware properties** in the memory map (`[HardwareValue]`/`[HardwareSwitch]`) — device state becomes inspectable/editable without per-device UI.
7. **Contention regression tests as xUnit theories** — per-opcode frame-tact sequences for 48K early/late and 128K ULAs, runnable in CI.

## 9. Gaps and caveats

- **Net loss of debugger capability versus ZXMAK2 with Adlers**: no conditional, memory-read/write or opcode breakpoints in the UI, no expression language, no trace/profile counters, no stack view, no comments/labels/symbols, no search, no disassembly export, no assembler, no graphics viewer. Config files that name `ZXMAK2.Hardware.Adlers.Debugger` or `DebuggerEx` no longer resolve *(inferred: types removed)*.
- No breakpoint list or management beyond toggle/clear-all; breakpoints are PC-only, logical (no bank), not checked while HALTED, and not persisted.
- No step out (WinForms button disabled, absent in text UI), no run-to-cursor, no watches, no history/rewind, no beam/raster visualization.
- The CLI has no debugger or scripting commands; "automation" exists only as the in-process test API and the GDB stub.
- GDB stub is unchanged, so its defects carry over: exec breakpoint removal never matches (reference equality), watch hits don't stop the VM, `g` omits PC, `s` bypasses breakpoint/frame bookkeeping, listens on all interfaces (`kozynax/src/ZXMAK2.Hardware.GdbServer/GDB/GDBSession.cs:247-252`, `:362-363`; `GDB/GDBNetworkServer.cs:45`, `:52-61`).
- Logging goes unconditionally to stderr at all levels; enabling `logIo` or `PORTDEBUG` floods the console with no file option.
- Naming inversion in the model: `SaveDataToFile` implements *load* and `ReadDataFromFile` implements *save* (`kozynax/src/Kozynax.UI/DebuggerDialog.cs:836-909`); behavior is correct, the names are swapped.
- Hex view character column shows only printable ASCII, losing ZXMAK2's ZX-charset mapping (`kozynax/src/Kozynax.UI/DebuggerDialog.cs:399-408`).
- `StdioTerminal` reads keys via `Console.ReadKey`; mouse, context menus by right-click and double-click editing are effectively SDL-cell-UI features *(inferred)*.
- The SDL debugger is a modal loop that replaces the emulator picture; no side-by-side screen while stepping *(inferred)*.
