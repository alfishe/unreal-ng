## Sequencing rationale (2026-09-27)

A lot of new scope arrived in one week: TSConf, ZX-Poly, NeoGS + GS debugger, video debug
translation, TTD v2, the core perf review, devtools/roadmap visions. Ordered by these rules:

1. **Defects in shipped features first.** The GS control-path race (#44) and the tape derail
   defects (#5 B1–B4) are fixed (2026-09-28); #5 keeps only the three unexplained tapes.
2. **Finish what is in flight before starting new things.** The beam refactor for #42 landed
   (`a0a12def`, `7ed8f2a9`) and #42a closed (`f0ff08e5`); #55 (ATM3, E0–E5 done) and #57 (+3,
   phases 1–4 done) are in flight.
3. **Foundations before new machines.** Every new device with its own RAM or video mode adds work
   to the TTD migration (#40) and the video mappers (#42). Do the TTD v2 **V0 + V1 memory
   regions** and the **#42 mapper interface** before TSConf (#41), ZX-Poly (#43) and NeoGS
   (#45), so these machines plug into the new model instead of adding to the migration work.
4. **The expression evaluator (#6) is the most-wanted shared piece.** Conditional breakpoints,
   `run_until_condition`, DeZog fast conditions, the trigger engine (roadmap), the devtools
   program (#51), the NedoOS struct DSL, and the ZX DLSS program's (#56) GigaScreen analyzer,
   trigger integration and pack authoring all consume it.
5. **Only one new-machine program at a time.** Pick between TSConf (#41: ancestor code
   half-ported, biggest user base) and ZX-Poly (#43: 1-week spike as a cheap decision gate).
   Recommendation: run the ZX-Poly spike opportunistically, commit to TSConf as the next
   machine program.
6. **Machine order (owner decision, 2026-09-28): infrastructure → migrate existing machines →
   TSConf → Sprinter, strictly in that order.** First finish the shared infrastructure:
   TTD v2 (#40), the video mappers (#42), the media manager (#58), the shared machine pieces (#60:
   programmable interrupt source, memory write intercept, any clock multiplier, one shared CMOS
   chip, wait states, per-model screen selection, raw PC floppies) and the IDE core (#13a). Then
   move BaseConf (#55) and the other existing machines (ATM710, Profi, Scorpion, +3) onto it, so
   no machine keeps a private copy of a shared piece. Then TSConf (#41). The Sprinter (#59) is the
   last machine program; with TSConf in place the owner started it on 2026-10-01.
