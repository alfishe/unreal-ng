# Scorpion ZS‑256 Turbo+ — декодирование GAL (fapch / turbo / profrom)

Источник: `romychs/Scorpion256TPlus`, каталог `GAL/`, схема `Export/Schematic_Scorpion-256-Turbo_v16.2.8a.pdf`,
образы `ROM/scorp401-E5476776.rom`, `ROM/scorp_prof401-Classic-Scorp-Profi.rom`.

Все уравнения ниже получены прямым разбором карт перемычек (скрипты `jed22v10.py`, `jed16v8.py`),
имена сигналов — из блоков `NOTE PINS` в JED и из подписей на схеме. Маппинг колонок 22V10 проверен на
`turbo.jed` (даёт осмысленные WAIT/CLK/RAS), маппинг 16V8 — на `fapch.jed` (получается связная таблица переходов).

## 0. Как читать JED (кратко)

- `0` — перемычка цела, вход подключён к терму; `1` — вход отключён. Строка из одних `1` = терм всегда истинен;
  строка из одних `0` (или отсутствующая при `F0`) = терм всегда ложен.
- **GAL22V10**: 44 колонки = 22 входа × (прямой, инверсный). Порядок пар колонок:
  `1, 2, 23, 3, 22, 4, 21, 5, 20, 6, 19, 7, 18, 8, 17, 9, 16, 10, 15, 11, 14, 13`.
  Строка 0 — AR; далее для OLMC 23…14: строка OE + 8/10/12/14/16/16/14/12/10/8 термов; строка 131 — SP.
  `L5808` — 20 бит S1,S0 для OLMC 23…14: **S1=1 комбинаторный / S1=0 регистровый; S0=1 прямой / S0=0 инверсный.**
- **GAL16V8**: 32 колонки, пары `2, 1|fb19, 3, 18, 4, 17, 5, 16, 6, 15, 7, 14, 8, 13, 9, 11|fb12`;
  `L2048` — XOR (1 = прямой выход), `L2120` — AC1, `L2128` — PTD (разрешение термов), `L2192` — SYN, `L2193` — AC0.

Обозначения: `!` — инверсия, `·` — И, `+` — ИЛИ, `:=` — регистровый выход (D‑триггер), `=` — комбинаторный.

## 1. FAPCH.JED — ФАПЧ сепаратора данных дисковода (DD59, GAL16V8)

Назначение: фазовая автоподстройка окна данных FDC (README: «контроллер дисковода с ФАПЧ»). Не имеет отношения
к «frequency/address patch».

Конфигурация: SYN=1, AC0=0 — **simple mode**, все OLMC выходные. `L2048 = 00001000` → XOR=1 только у пина 15 (D3),
остальные выходы **инверсные**. `L2128` — все термы разрешены (это PTD, не подпись).

| Пин | Имя | Направление |
|---|---|---|
| 5 | A4 | вход — импульс данных |
| 6 | A3 | вход — обратная связь (регистр ТМ9) |
| 9 | A2 | вход — обратная связь |
| 8 | A1 | вход — обратная связь |
| 7 | A0 | вход — обратная связь |
| 15 | D3 | выход, прямой |
| 12 | D2 | выход, инверсный |
| 13 | D1 | выход, инверсный |
| 14 | D0 | выход, инверсный |

Термы:

```
 D3 = A3·!A1 + A3·!A2 + A4·A3·!A0 + A4·!A3·A0·A1·A2

!D0 = !A4·A3·A1·!A2 + !A3·A0·A2 + A4·A0 + !A4·!A0·A1·!A2 + !A4·A3·!A0·A1

!D1 = A4·A0·A1 + A4·!A0·!A1 + !A4·!A0·A1·A2 + !A4·A0·!A1·!A2
    + !A4·A3·!A0·A1 + !A4·A3·A1·A2 + !A4·!A3·A0·!A1 + !A4·!A3·!A1·!A2

!D2 = !A0·!A1·!A2 + A4·A0·A1·A2 + A4·!A0·!A2 + A4·!A1·!A2
    + !A4·A3·A1·A2 + !A4·!A3·!A0·!A1 + !A4·!A3·!A2
```

Таблица переходов (вход A4 A3..A0 → выход D3..D0), вычислена из термов:

```
A4=1 (нет импульса):  D = (A3..A0) + 1 mod 16        — свободный счёт
A4=0 (импульс):       0→1 1→1 2→2 3→3 4→3 5→4 6→5 7→6
                      8→B 9→D A→C B→E C→F D→F E→0 F→1
```

Интерпретация: D3..D0 защёлкиваются регистром и возвращаются на A3..A0 — 16‑фазный счётчик. Без импульса он
инкрементируется, при импульсе фаза корректируется: состояния 0…7 «притормаживаются», 8…F «подталкиваются»,
E/F перебрасываются в 0/1. Окно данных подтягивается к фронту импульса — классическая цифровая ФАПЧ.

## 2. TURBO.JED — контроллер турбо‑режима и памяти (DD30, GAL22V10, «TURBO 15.3»)

| Пин | Имя | Тип |
|---|---|---|
| 1 | CLK_7MHZ | вход/такт |
| 4 | IORQ_ | вход |
| 5 | WR_EN | вход |
| 6 | RAM_ | вход |
| 7 | INT | вход |
| 8 | TRB_IN | вход |
| 9 | BORDER_ | вход (**ни в одном терме не используется**) |
| 10 | M1_ | вход |
| 11 | H0 | вход (**не используется**) |
| 13 | H1 | вход |
| 14 | H1M | комб., прямой |
| 15 | Pin13 | **регистровый**, инверсный — единственный триггер |
| 16 | WR_BUFF | комб., прямой |
| 17 | RAS_ | комб., инверсный |
| 18 | TRB | комб., инверсный, OE отключён (внутренний узел с обратной связью) |
| 19 | WE | комб., инверсный |
| 20 | CLK_CPU | комб., прямой |
| 21 | WAIT_ | комб., прямой |
| 22, 23 | — | не используются (OLMC без термов, OE отключён) |

`L5808 = 00 00 11 11 10 10 11 00 11 00` (пины 23…14).

```
WAIT_   = INT + TRB_IN·!M1_·!H1 + TRB_IN·!WR_BUFF·!M1_ + !CLK_CPU·WE·!M1_
CLK_CPU = CLK_7MHZ·!INT + INT·!TRB_IN
!WE     = INT·H1 + WR_BUFF·H1 + TRB_IN + !CLK_CPU
!TRB    = !INT·H1 + !INT·!TRB_IN + CLK_CPU·!INT + !WE·!INT
        + !CLK_CPU·WE·TRB·TRB_IN·!RAS_·!H1
!RAS_   = H1M
WR_BUFF = H1M·!H1 + !INT·!WR_BUFF·H1M
!Pin13 := M1_ + WAIT_                      (D‑триггер, такт CLK_7MHZ)
H1M     = INT·H1 + WR_BUFF·H1
```

Замечания: TRB и WR_BUFF — комбинаторные защёлки на обратной связи, а не регистры. Пин 22 — свободный OLMC,
а не «VCC pull‑up». Никакой логики «wait states во время бордюра» в схеме нет: BORDER_ и H0 в термы не входят.

## 3. PROFROM.JED — селектор плоскостей ProfROM (DD41, GAL22V10)

### 3.1. Подключение по схеме

| Пин GAL | Имя в JED | Реальный сигнал (схема) |
|---|---|---|
| 1 | clk | `RDR-` — «Чтение ПЗУ» (он же /CE ПЗУ DD29) |
| 2 | A15 | `CS1` → ROM A15 (выбор 16K‑страницы: сервис/DOS) |
| 3…9 | A12, A7, A6, A5, A4, A3, A2 | шина адреса Z80 |
| 10, 11 | — | **GND** |
| 13, 14 (sw), 16 (p16) | — | не подключены |
| 15 | A14 | `CS27` → ROM A14 (выбор 16K‑страницы: 48/DOS) |
| 17…21 | A10, A11, A9, A8, A13 | шина адреса Z80 |
| 22 | A16 | → ROM A16 |
| 23 | A17 | → ROM A17 |

ПЗУ DD29 — W27C020 (256K×8): A0–A13 от Z80, A14 = CS27, A15 = CS1, A16/A17 от GAL.

### 3.2. Что реально прошито

`L5808 = 10 10 01 01 01 01 01 00 01 11`: A17, A16 — комбинаторные инверсные; sw — комбинаторный прямой;
p16 — регистровый инверсный без D‑термов (константа); остальные OLMC — входы.

```
!A17 = !CS1·!p11 + CS1·A10·!p16·p11 + !CS1·!A10 + !A10·p16·p11
!A16 = !A12·!p11 + A12·p16·p11 + !CS1·!A12·!p16 + CS1·!A12·!A10
 sw  = A17·!A16·A6·!A3·!A4·!A5·!A7·!A8·!A9·!A11·!A13·!p10
 p16 := (пусто)
```

С p10 = p11 = 0 (как на схеме):

```
A17 = CS1
A16 = A12
sw  — декодирует #0040…#0043 (A10, A12 — безразличны), никуда не заведён
```

**Вывод:** этот JED не реализует переключение плоскостей. Нет состояния (p16 ничего не защёлкивает, обратной
связи от A16/A17 через триггеры нет), а `sw` декодирует не тот адрес и не подключён. С такой прошивкой 256K‑образ
из `ROM/` не загрузится: окно 0000–0FFF берётся из плоскости 0, 1000–1FFF — из плоскости 1 и т.д.
Файл (2007 г., ispLEVER) — заглушка или несогласованная с платой версия.

### 3.3. Реальный протокол ProfROM (по прошивке и MAME `sinclair/scorpion.cpp`)

Порта ввода‑вывода нет. Плоскость (2 бита → ROM A16, A17) меняется **чтением** ПЗУ:

- условие: в окне 0000–3FFF стоит страница сервис‑монитора (#1FFD бит 1 = 1);
- триггер: чтение адреса `#0100 + 4·S`, `S = A3:A2`;
- новая плоскость = `f(S, текущая)`:

```
S  адрес   тек.: 0  1  2  3
0  #0100         0  1  2  3    (без изменений)
1  #0104         3  3  3  2
2  #0108         2  2  0  1
3  #010C         1  0  1  0    (P ^ 1)
```

Подтверждение в образе: в плоскостях 1–3 по #0111 лежит заглушка, копируемая в #5BEE:
`LD BC,#1FFD / LD A,2 / OUT (C),A / LD HL,#010C / LD L,(HL) / XOR A / OUT (C),A / JP 0`
(плоскость 2 читает #0108: 2→0; плоскости 1 и 3 читают #010C: 1→0, 3→0).
Байты сервис‑страницы по #0100: `E5 02`, `01 06`, `01 0A`, `01 0E` — `(#0101)>>2 & 3` = номер плоскости.

Для ПЗУ больше 256K (Scorpion GMX / ZS‑1024) используется другая схема: порт #7EFD, биты D4–D6 → A16–A18
(28F400, 512K), с защёлкой «fixrom».

### 3.4. Логика, которую GAL должен реализовывать

Такт — `RDR-` (каждое чтение ПЗУ), два регистровых выхода P1→A17, P0→A16 с удержанием. A0/A1 в GAL не заведены,
поэтому #0100…#0103 эквивалентны.

```
T  = CS1·!CS27·A8·!A13·!A12·!A11·!A10·!A9·!A7·!A6·!A5·!A4      ; сервис‑страница, адрес #01xx, A7..A4 = 0

P1 := !T·P1 + T·!A3·A2 + T·A3·!A2·!P1
P0 := !T·P0 + T·!A3·A2·!(P1·P0) + T·A3·!A2·P1·P0 + T·A3·A2·!P0
```

Разложение таблицы по битам: S=1: P1'=1, P0'=!(P1·P0); S=2: P1'=!P1, P0'=P1·P0; S=3: P1'=0, P0'=!P0; S=0: удержание.
Укладывается в 22V10 (≤10 термов на OLMC). Сброс плоскости в 0 по RES‑ следует добавить через AR.
