# A/B: the shared memory path changes of the Next (N2, N3b) on non-Next machines (2026-11-20)

Closes the TODO item "A/B benchmarks: the N2 `Read/WriteDebugEffects` Debug lean (+0.8 %) on a quiet machine, the N3c
changes". Question: do the shared-path changes made for the Next cost the other machines anything, and does such a cost
remain on master (`7027050a5`)?

## Verdict

- **N2 (`b1ee206c7` against `3082b81e8`)**: a real cost on the Debug path. `MemoryReadDebug` / `MemoryWriteDebug` were one
  function each; after the extraction the compiler kept `ReadDebugEffects` out of line (`bl` and a stack frame per
  debug read) and `WriteDebugEffects` as a tail call. Debug variants +1.2 % on average (48K +2.5 %, Pentagon +1.7 %,
  Scorpion +1.5 %, 14-16 of 20 rounds positive). The Fast variants of the same machines lean +1.0-1.5 % too (code
  layout of the rest of the commit: the Fast path did not change), so the part due to the call is about +0.2-1.1 %.
- **N3b (`b93fe36ac` against `33cbd360c`)**: no cost. `ModelMemoryInterface(debug, contended)` and the virtual
  `RefreshSlotContention` run at an interface or video mode switch, not per access; `MemoryReadDebug` is the same
  23-instruction body on both sides. Mean of the per-round ratios +0.05 % (Debug -0.17 %, Fast +0.24 %), inside the A/A.
  The N3c commit itself (`1b868c3cc`) touches only Next files.
- **Master (`7027050a5`)**: the N2 cost is still there and larger. `ReadDebugEffects` grew (read taps, the access
  probe, fast-RAM pages) and is still a call. Forcing its body inline into `Memory::MemoryReadDebug` (the fix below)
  makes the Debug frames of the 16K-window machines 2-5 % faster (48K -4.3 %, Pentagon -4.8 %, Scorpion -3.2 %,
  ATM3 -2.9 %, 0-3 of 20 rounds the other way), Debug mean -2.9 %; the Fast variants do not change (mean -0.6 %, no
  benchmark worse than +0.3 %). TS-Conf and the Sprinter have their own `MemoryReadDebug` and do not move.
- Inlining `WriteDebugEffects` as well (a first variant) gained nothing more on Debug (-2.5 %) and moved several Fast
  benchmarks by +1 % (layout: TS-Conf, Scorpion, 48K, NeoGS card-tight +3.5 % in 20 of 20 rounds), so the fix inlines
  the read only.

## The fix

`core/src/emulator/memory/memory.h` / `memory.cpp`: the body of `ReadDebugEffects` moves into a private
`__forceinline ReadDebugEffectsInline` (memory.cpp only), which `Memory::MemoryReadDebug` calls; `ReadDebugEffects`
stays the out-of-line entry for `NextMemory`. No behavior change. Disassembly (arm64, Release): `MemoryReadDebug` 23
instructions with a `bl ReadDebugEffects` on master, about 260 with no call to it after the fix; the write path is
unchanged.

## Method

- Host: the remote M3 Ultra build host (32 cores), Release `-DBENCHMARKS=ON`, Apple clang of the host, `core-benchmarks`
  built by `tools/build/build.sh core-benchmarks` in one detached worktree per commit; no build fixes were needed on the
  old commits.
- `UNREAL_NICE=0 ./core-benchmarks --benchmark_filter=BM_HostFrame_ --benchmark_out=X.json --benchmark_out_format=json`
  from each build's `bin`, all `BM_HostFrame_*` of the tree (26 then, 29 now), CPU time.
- Interleaved rounds: the labels in the given order on odd rounds, reversed on even rounds, 20 rounds.
  - Run 1 (historical): `3082b81e8` (A1), `b1ee206c7` (N2), `33cbd360c` (N3a), `b93fe36ac` (N3b), `3082b81e8` again
    (A2, the A/A). Host load 9-190 (other sessions' builds; 30-80 most of the time).
  - Run 2: master (M1), fix with both effects inlined, master again (M2). Load 11-55.
  - Run 3: master (M1), both inlined, read only inlined (the fix), master again (M2). Load 3-29.
- Statistic: for each benchmark the median of the 20 per-round ratios B/A, and how many rounds have B > A; the tables
  below also give the median and range (min..max) of each side. "Debug" / "Fast" lines: the mean and median of the
  per-benchmark values. The A/A (one binary in two positions of each round) is within -0.3 .. +0.8 % per benchmark in
  run 3, within +-0.5 % in run 2 but one outlier (TSConf14_256C -2.0 %), and within -1.4 .. +0.5 % in the loaded run 1;
  the 1.8 % bias known for this host did not show.
