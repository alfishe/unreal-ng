## Reference: real BaseConf hardware (+ NedoOS usage)

**Which BaseConf is "real".** The repo holds two FPGA trees. They are NOT the same hardware:

| Alias | Path | Status |
|---|---|---|
| **BC** (legacy) | `P/fpga/baseconf/trunk` | Frozen at the 2020-11-14 restructure (`f4d906bb`). Config read-back is on **#xxBE**, no TR-DOS trap. |
| **TD** (current release) | `P/fpga/base_trdemu/trunk` | All "baseconf:" commits since 2020 land here (for example `663b8cf2` 2023-06-17 "removed completely xxBE read ports", `6bab9e30` 2024-02-10). Config read/write moved to **#xxBD**; #xxBE is write-only (end NMI / end emulation). Adds the TR-DOS emulation trap, the 12-bit (444) palette, an 8-bit Kempston port and a 2-entry cache. Shipped as `P/cfgs/standalone_base_trdemu/trunk/zxevo_fw.bin`. |
| newirq | `zxevo.pentevo/fpga/base_trdemu/newirq` | Work in progress (2026-01). "Enhanced" interrupts on #14BD/#15BD/#16BD (vectors 0xC7..0xFF, per-source enable and status bits). Described in the 2026 document but **not in the release**. |

### Notes: bugs, hacks and oddities
1. **Z-Controller on ATM3 is only half-wired.** Writes to #xx77 never reach `TZc::Wr`: io.cpp:111-121 routes only #57 for ATM3, and in shadow #xx77 is FF77. `Zc.Reset()` is never called anywhere, so `Cfg=0` from static zero-init. The effect is that SD CS stays permanently asserted and card deselect/reselect is never seen. It works for a simple driver, but not for code that relies on the CS edge.
2. **Precedence bug** at io.cpp:1005, `conf.zc && (p1 == 0x57) || (p1 == 0x77)`: every #xx77 read, on every model and even with ZC off, returns `Zc.Status` (0).
3. **The SD card is SDSC-only with a fixed 1 GiB CSD**: C_SIZE=4095, MULT=7, BL_LEN=9. OCR CCS=0, so SDHC-only drivers see a small card. CMD18 prefetches the next block with `fread` at block end, with no seek.
4. **AVR version readout is fake**: fw and bootloader give the same "UnrealSpeccy" + build date. The PS/2 FIFO is exposed on all of #F0-#FF while enabled. A CMOS #0C write flips the **host** CapsLock (memory.cpp:588-595).
5. **Turbo "14 MHz" runs at about 10.5 MHz** (`turbo(3)`). No Evo wait-state or contention model.
6. **#xxBE/#xxBF/#xxBD are decoded regardless of shadow mode**, low byte only. Only BE indices 0x00-0x0E exist. #xxBF bits 1-2 (ROM write, font write) are ignored, so no flash programming and no font RAM.
7. **Shadow exit is "M1 from RAM"** (`CF_LEAVEDOSRAM`), not an address test. Entry checks #7FFD.4 rather than the page actually mapped at #0000.
8. **CMOS moves to #DEF7/#BEF7 in shadow**, because #xFF7 is decoded on 12 bits there (lvd fix, io.cpp:305-314, 917). #EFF7 written in shadow lands in a page register, as on real hardware.
9. The ini defaults are not Evo-like: `HIMEM=TSL`, `Scheme=AYX32`, `Chip=YM2203`, `MoonSound=1`, and `NEMO-DIVIDE` with both HDD and SD pointing at `wc.img`. The stale `[ROM.ATM3]` pages (0/13/2/3) do not match the zxevo.rom layout (28/29/30/31).
10. The palette write also passes through to the WD system port #FF (intentional, io.cpp:317). SAA1099 would also claim #xxFF outside shadow if enabled.
11. The pentevo copy of Unreal adds only robustness fixes. One is `vid.memcpucyc[min(cpu.t/VID_TACTS, VID_LINES-1)]` (z80_main.inl:44, 53, 149), which avoids an out-of-range index at high `cpu.t`; `/224` can overflow in turbo modes in this tree.

### Notes

1. **Upstream ATM3 is an "ATM3 / early PentEvo" model and has major gaps.**
   - `#EFF7` is not decoded at all.
   - The #7FFD extension bits are ignored.
   - No turbo.
   - #77 CS is not emulated and the SD model is SDSC-only.
   - The #BE read map stops at #0D.
   - No AVR/PS/2.

   N (lvd/thims/DimkaM) supplies most of what BaseConf needs:
   - #EFF7, 6-bit #7FFD mix, RAM0 at 0000.
   - #BD breakpoint and FDD-trap mask.
   - #0B/#0E/#10/#11/#13/#14BE.
   - PS/2 FIFO through CMOS #F0+, SDv2-style CMD8/CMD58, INT not gated.
   - 12-bit palette (#BF.5).

   S is N plus debugger and GUI work. It does not change Evo hardware semantics.
2. **Still missing in every variant:**
   - Turbo 7/14 MHz from ports (#xx77 D3, #EFF7.4). S and N only fake it with a larger `Frame`.
   - Flash/ROM write (#BF.1).
   - Z-Controller CS through #77 (the card is always selected) and #77 status bits.
   - SDHC block addressing, so images are limited to 2 GB (`fseek(long)`).
   - #0FBE, #12BE.
   - AVR config registers #0C-#0F, real AVR/bootloader version bytes, SPI-flash access.
   - Evo DMA, ZiFi, RS-232.
3. Real-hardware conformance of the #BE map and the NMI/RAM-#FF semantics was taken from the emulator code only. It was not cross-checked against the BaseConf doc here, although the S comments cite `zxevo_base_configuration.pdf` (07.01.2022). One upstream detail differs from N: in U, `#0CBE` D4 is the *current* `CF_TRDOS`; in N it is the DOS state latched at NMI entry.
4. Side issues noticed, not investigated further:
   - U `io.cpp:163/815`: `(((p1>>5)-1) < 5)` is also true for port #0F (index -1), so shadow-mode I/O on #0F reads/writes `wd_shadow[-1]`. N fixed the condition.
   - S `io.cpp:1879-1882`: a dangling `else` means the Z-Controller is never decoded on OUT for non-ATM3 models.
5. Line numbers for N and S refer to the original files. Only encoding was converted (cp1251 to UTF-8) and CR stripped for reading; the line count is unchanged.

### Notes: bugs and TODOs
1. **Xpeccy turbo bug.** `evoOutEFF7` uses `EFF7.b3` (the RAM0 bit) as the turbo bit, while `evoOut77d` uses b4. So writing `#EFF7` can flip the clock (X:pentevo.c:226 vs 296). This is fixed in P (P:pentevo.c:460-465).
2. **Xpeccy CMOS address is 7-bit.** `cmos_wr(CMOS_ADR)` masks with 0x7F (X:cmos.c), so the AVR extension triggers at 0x70 or above. Real cells 0x70-0x7F are shadowed, and 0x80-0xEF alias 0x00-0x6F. P fixes this and migrates old files (P:machines.cpp:633-641).
3. **Shadow gating.**
   - X opens the shadow ports when `prt2.b7` (A14 of `#xx77`) = 0. After reset, `prt2 = 0x03`, so the shadow ports are always open.
   - P uses A9 (`prt2.b6`), matching the "CP/M mode holds DOS" semantics, and resets with A14 = 1.
   - X also forces RAM0 at 0000 even with the pager off (X:pentevo.c:88).
4. **AlCo mode code 0x13 is unreachable.** The mode word is `EFF7&0x20 | (EFF7&1)<<1 | p77&7`, so bit4 is never set. The "alco" case `0x13` never matches, and `EFF7.b5` + ZX mode (0x23) selects HWMC instead. Real BaseConf: `EFF7.b5` = AlCo? or HWMC? This needs a cross-check against the other emulator columns. There is also a second problem: `(EFF7&1)<<1` lands on the same bit as `#xx77` b1, so with ZX mode (`#xx77` = 3) `EFF7.b0` does nothing. As a result, Pentagon 16-color (EFF7.b0) cannot be reached in ZX mode. The code is the same in both forks (X:21-33, P:32-44).
5. **SD card.**
   - `sdcWrite` has `if ((sdc->arg[0] = CMD25) && ...)`: an assignment instead of a comparison. It clobbers `arg[0]` and applies the `0xFD` stop token to CMD24 as well (X:sdcard.c:253, P:sdcard.c:287).
   - CMD9/CMD10/CMD13 are unimplemented, so there is no CSD/CID.
   - The card is always reported as SDHC (OCR CCS = 1).
   - `sdcSetCapacity` is stubbed out.
   - `int sz = ftell` limits image files to under 2 GB.
6. **PS/2 on Xpeccy is dead.** Mode 2 of `#F0` never gets codes because the Evo keyboard core is `KBD_SPECTRUM` and `xt_press` is commented out. P wires it in `evo_keyp`.
7. **Version strings.**
   - X: `"xEvo "` 09.12.2012 (release) and `"xBoot"` 24.01.2012.
   - P: returns `"Xpeccy+"` + build date for **both** mode 0 (baseconf) and mode 1 (bootloader), on the grounds that an emulator should not claim a real 2012 FPGA build (P:spectrum.c:566-583).
8. **RTC.** Weekday 0-6 instead of 1-7. Register B 12h/binary are TODOs, and there are no alarm or periodic IRQs. In P, 0x0A reads 0 (UIP never set) and 0x0B is forced to 0x02.
9. **P's deliberate deviation.** A virtual TR-DOS drive that holds an inserted disk goes to the real FDC (P:pentevo.c:304-312), and `#FF` writes never trigger trdemu.
10. **Not implemented in either.**
    - ROM/flash writes (`#BF.b1`).
    - SPI flash.
    - `#xx77` read status.
    - `#14BE-#16BE` (stubs in P).
    - DMA, ZiFi, RS232.
    - Wait states.
    - An SAA or NeoGS option for Evo.
    - AVR/ERS SD boot beyond what the ROM itself does.
11. **atm2.c** also differs between the repos. It is not used by `HW_PENTEVO`; the Evo core is self-contained in `pentevo.c` plus the shared `common.c`, `cmos.c`, `sdcard.c` and `hdd.c`.

### Notes: bugs and TODOs

1. **#00BE..#07BE bug.** `GetCfgPage((addr & 7) >> 8)` (`MemoryPentEvo.cs:462`) always evaluates to index 0, so all eight page read-backs return window 0. The intended code is `(addr >> 8) & 7`.
2. **#7FFD lock bug in Pentagon-1024 mode.** `m_lock = (CMR0 & 0x20) != 0` (`:132`) applies even when #EFF7 bit2 = 0, where D5 is a page-extension bit. Selecting any page with D5 set therefore locks #7FFD.
3. **Shadow gating is inconsistent.** SD uses only `SYSEN` (#BF bit0), so in plain DOS mode (DOSEN=1) a #xx77 write goes to both the ATM #77 system port *and* the SD CS latch. #xxBE, #xxBF, #EFF7 and IDE are never gated.
4. **The SD CS line is ignored** (`card_cs` is written but never read), and the card is SDSC-only (byte addressing, CCS=0, fixed CSD).
5. **DOS exit happens only on an M1 from RAM.** An M1 from a ROM window at >=#4000 keeps DOSEN. DOS entry does not verify that the ROM is BASIC48, and the M1 path ignores `W0RAM0`.
6. **Stored but unimplemented bits:** TURBO (#EFF7 b4, #77 D3), Z_I HSYNC INT (#77 D5), #BF bit1 ROM-write, bit3+.
7. **CMOS.** Day of week is 0-based (Sunday=0), reg 0x0B always reads 0x02, UIP is never set, RTC writes are ignored, and the PS/2 FIFO always returns 0. Source comments ("посмотреть состояние по сбросу" = "check the state on reset", "посмотреть поведение по другим кодам" = "check the behavior for other codes") mark the reset mode and the unknown-mode codes as unverified (`CmosPentEvo.cs:104,227`).
8. **No TurboSound, tape, GS, SounDrive, SAA or joystick** on the Evo machine, though GS exists in the codebase. ZX-matrix keyboard only.
9. `UlaPentEvo.cs:33` flash period is marked `// TODO: check?`. `UlaAtm450.cs:93` has a TODO about palette substitution. `UlaAtm450.cs:294` has a FIXME about frame params in the turbo ULA.
10. kozynax's only functional Evo change is SD image persistence plus null safety. There are no fixes to any of the bugs above.

### Notes
- **Bugs and quirks found (all in MAME code, not hardware facts):**
  1. #EFF7 bit3 maps ROM page 0, not RAM page 0 (pv:177-178).
  2. #12BD write clears all RO bits because of a shadowed variable (pv:331-339).
  3. The #11BE/#11BD breakpoint high byte is lost (pv:310-312, 328-330). The breakpoint is never used.
  4. fddvirt compares the whole #FF sysreg byte with a 4-bit value (pv:156, 181).
  5. The PS/2 keyboard read hijacks every #BFF7 read while ext = 2 (pv:519-520).
  6. The ZX 16c mode is a stub (pv:393).
  7. Kempston joystick is hardwired to 0 (pv:597).
- **I/O view semantics:** `m_io_view[0]` (normal) is empty and `m_io_view[1]` (shadow) adds DOS ports. The always-mapped ports (7FFD, FE, AY, BF, BE/BD, EFF7, DFF7/BFF7, NemoIDE, SPI #57/#77, mouse) sit outside the view. As a result, **NemoIDE and SD are also reachable in shadow mode, and #xxBE/#xxBF are reachable outside it** (no shadow gating).
- **Not modelled:** the AVR MCU (only the F0 version stub and the PS/2 scan-code read), flash programming, TR-DOS emulation traps, wait states for 14 MHz, and contention.
- TS-Conf (`tsconf.cpp`, `tsconf_m.cpp`) is a separate driver. It reuses `glukrs` and `spi_sdcard`; its DMA, copper and RS232 do not apply to BaseConf.
