# Generation pipeline for the Scorpion monitor listings

The scripts and curated data here regenerate and verify the three
annotated service-monitor listings one level up
(`../base/scorpion-monitor-p2.asm`, `../base/scorpion295-monitor-p2.asm`,
`../prof/scorpion-prof401-monitor-p2.asm`).  See the
[parent README](../README.md) for the ROM background; this file documents
the tooling itself.

Prerequisites: Python 3 and `z80dasm` 1.2.0 on `PATH`.

## Contents at a glance

| File                   | Kind     | Role |
|------------------------|----------|------|
| `extract.py`           | tool     | slice the monitor page out of each ROM bundle |
| `analyze.py`           | tool     | auto code/data analysis, first `.blocks` draft |
| `fixblocks.py`         | tool     | hand-verified block corrections |
| `renblocks.py`         | tool     | rename/split data blocks, free misclassified code |
| `align.py`             | tool     | byte-run alignment base -> sister ROM |
| `mapsig.py`            | tool     | resolve ambiguous symbols via block signatures |
| `dict_scorpion.py`     | curated  | base symbols, comments, file header |
| `dict_scorp295.py`     | curated  | v2.95 dict, derived from the base |
| `dict_prof401.py`      | curated  | v4.01 dict, derived from the base |
| `gen.py`               | tool     | z80dasm run + comment/header insertion |
| `checkcov.py`          | tool     | byte-exact listing verification |
| `auditblocks.py`       | tool     | every `; BLOCK` header must be named+explained |
| `mon_*_p2.blocks`      | curated  | code/data block maps (final, refined) |
| `map_mon_*_p2.json`    | curated  | base->sister symbol address maps (from `align.py`) |
| `mapsig_prof401.json`  | curated  | signature-resolved symbols (from `mapsig.py`) |
| `digest_*.txt`         | curated  | per-address instruction text for `mapsig.py` |
| `mon_*_p2.bin`         | derived  | monitor pages, regenerated by `extract.py` |

"Curated" files are the ones to edit when refining; everything else can
be rebuilt from them and the ROM bundles.

## Pipeline overview

```
data/rom/*.rom --extract.py--> mon_*_p2.bin
                                  |
                    analyze.py    v          (first draft only)
                    fixblocks.py --> mon_*_p2.blocks
                    renblocks.py -->          (refined block map)
                                  |
   dict_scorpion.py --align.py--> map_mon_*_p2.json --mapsig.py--> mapsig_*.json
        |                |                                          |
        +--------------- +-------- dict_scorp295.py / dict_prof401.py
                                                           |
mon_*_p2.bin + mon_*_p2.blocks + dict_*.py --gen.py--> ../{base,prof}/*.asm
                                                           |
                        checkcov.py, auditblocks.py <------+
```

Steps 1-3 (analyze/fixblocks/renblocks) only need re-running when the
block map itself changes; day-to-day refinement is: edit a `dict_*.py`,
re-run `gen.py`, verify with `checkcov.py` + `auditblocks.py`.

## Script reference

### extract.py - page extraction

`python3 extract.py` (no arguments).  Slices file offset $8000-$BFFF
("p2", the service monitor) out of `data/rom/scorpion.rom`,
`data/rom/scorp295.rom` and `data/rom/scorp_prof401.rom` into the three
`mon_*_p2.bin` files next to this script.  The repo root is found by
walking five levels up from the script directory.

### analyze.py - automatic code/data analysis

`python3 analyze.py <page.bin> <out.blocks>`.  A dedicated Z80
instruction-length decoder classifies every byte (code, string data,
table data, filler), walks jump/call targets for reachability and emits
a z80dasm block-definition file with auto-numbered `blkNNN` names.
This is only the first draft: its output is then corrected by
`fixblocks.py` and `renblocks.py`.

### fixblocks.py - hand-verified corrections

`python3 fixblocks.py [<job>]` - applies per-ROM operation lists
(delete/shrink/move/retype/...) to the `.blocks` files.  Every fix was
verified by decoding the bytes and cross-checking the sister ROMs where
the same routine sits relocated.  Optional argument runs a single job.
Edits the files in place; keep the `.blocks` files under git so the
corrections stay reviewable (only `renblocks.py` makes a `.bak2`).

### renblocks.py - block naming

`python3 renblocks.py` (no arguments).  Renames and splits the remaining
auto-numbered `blkNNN` data blocks into meaningful names
(`KeyScanTableA`, `MsgOff`, `EncodedTable3690`, ...) and frees regions
that are really code (v2.95 `$0A19` key-scan routine, `$2818` help
screen, the ROM-tail menu builders).  Idempotent: operations are keyed
on current block names and re-runs are no-ops.  Writes a `.bak2` backup
before the first change of a run.

### align.py - base-to-sister alignment

`python3 align.py <sister stem> <dict.py>`, e.g.
`python3 align.py mon_scorp295_p2 dict_scorpion.py`.  Finds equal byte
runs between the base page and the sister page, then maps every base
symbol below $4000 to its sister address (RAM equates >= $4000 stay).
Writes `runs_<stem>.json` (intermediate, disposable) and
`map_<stem>.json` (curated input for the sister dict).  Unmapped
symbols are printed - those get hand-resolved entries in the dict.

### mapsig.py - signature resolution

`python3 mapsig.py <digest stem> <map json>`, e.g.
`python3 mapsig.py digest_scorp295 map_mon_scorp295_p2.json`.  For
symbols `align.py` could not map, builds a normalised instruction
signature (absolute hex numbers masked) around the symbol from the base
digest and searches for a unique window match in the sister digest;
prints a JSON address map to stdout (redirect to capture, as was done
for `mapsig_prof401.json`).  `dict_prof401.py` consumes that file.

### dict_scorpion.py - the base dictionary

The hand-written reference for the v2.x monitor.  Exports the interface
`gen.py` loads dynamically:

- `SYMBOLS` - list of `(address, name)`; code labels first, RAM equates
  (>= $4000) last.  Names are PascalCase per the project convention.
- `COMMENTS` - list of `(address, [text lines])`; inserted above the
  first instruction/data byte at that address (walking up over labels,
  `; BLOCK` headers and blank lines), wrapped in `;-` separator rules.
- `DATA_COMMENTS`/`DATA_ADDRS` - the data-block documentation subset;
  `DATA_ADDRS` lets the sister dicts skip these during inheritance and
  document their own relocated blocks instead.
- `HEADER` - the educational file header (RST API, RAM workspace map).

### dict_scorp295.py / dict_prof401.py - the sister dictionaries

Each loads `dict_scorpion.py` as the base, then:

- relocates inherited symbols via `map_mon_*_p2.json` (from `align.py`),
  refined by `mapsig_prof401.json` for v4.01, and overrides/extends them
  with hand-resolved `SYMBOLS` entries where alignment could not decide;
- drops comments listed in `DROP`, rewrites `$`-address references in
  inherited comments (`rewriteRefs`), skips `base.DATA_ADDRS` comments
  and appends its own version-specific comments instead;
- rewrites the `HEADER` (sister list, version-specific notes).

Anything they print as `WARNING: comment at $XXXX ... dropped` means an
inherited comment could not be relocated - the build is expected to
produce zero such warnings.

### gen.py - listing generation

`python3 gen.py <page.bin> <blocks> <dict.py> <out.asm>`.  Builds a
temporary symbol file from `dict.SYMBOLS`, runs
`z80dasm -a -l -t -g 0x0000 -b <blocks> --sym-input <sym>`, then
post-processes: block-derived `name_start/end` labels collapse onto
co-located user symbols (`normaliseBlockNames`, with duplicate-label
dedup), comments are inserted at their addresses, and the `HEADER`
replaces the `org` banner.  Temporary files are removed; the listing is
self-contained afterwards.

### checkcov.py - byte-exact verification

`python3 checkcov.py <listing.asm> <page.bin> [<listing> <bin> ...]`.
Every `;ADDR  xx xx ...` annotation run must reconstruct the 16 KiB page
exactly - gaps, overlaps and value mismatches are all reported.  A
listing is only valid at `16384/16384 bytes verified`.

### auditblocks.py - block documentation audit

`python3 auditblocks.py <listing.asm> ...`.  Every `; BLOCK 'name'`
header must have a comment mentioning that name within 25 lines above
it; `Tok*` records (the v4.01 tokenizer list) are exempt, covered by
the `TokenTable` comment.  Expect `0 without comment` per file.

## Data file formats

- `.blocks` - z80dasm block syntax, one block per line:
  `Name: start 0xNNNN end 0xNNNN type code|bytedata` (end exclusive;
  addresses are page-relative).  Only data blocks and deliberately
  carved code blocks are listed; unlisted bytes disassemble as code.
- `map_mon_*_p2.json` - `{symbol: sisterAddress|null}` for every base
  symbol (null = hand-resolve in the dict).
- `mapsig_prof401.json` - `{symbol: address}` resolved by signature.
- `digest_*.txt` - one line per instruction start,
  `NNNN <z80dasm instruction text>` (sorted by address), produced once
  from the initial raw disassembly of each page.  The instruction text
  is tied to that historical snapshot (it contains the original
  `blkNNN` label references), so the digests are preserved as inputs
  rather than regenerated.

## Workflows

Refine comments or symbols (day-to-day):

```sh
# edit dict_scorpion.py (or a sister dict), then from this folder:
python3 gen.py mon_scorpion_p2.bin mon_scorpion_p2.blocks dict_scorpion.py \
    ../base/scorpion-monitor-p2.asm
python3 checkcov.py ../base/scorpion-monitor-p2.asm mon_scorpion_p2.bin
python3 auditblocks.py ../base/scorpion-monitor-p2.asm
```

Full rebuild from the ROM bundles:

```sh
python3 extract.py                       # mon_*_p2.bin
# (analyze.py + fixblocks.py + renblocks.py only if the block map must
#  be redone from scratch - normally the curated .blocks files are kept)
python3 gen.py mon_scorpion_p2.bin mon_scorpion_p2.blocks dict_scorpion.py \
    ../base/scorpion-monitor-p2.asm
python3 gen.py mon_scorp295_p2.bin mon_scorp295_p2.blocks dict_scorp295.py \
    ../base/scorpion295-monitor-p2.asm
python3 gen.py mon_prof401_p2.bin mon_prof401_p2.blocks dict_prof401.py \
    ../prof/scorpion-prof401-monitor-p2.asm
python3 checkcov.py \
    ../base/scorpion-monitor-p2.asm mon_scorpion_p2.bin \
    ../base/scorpion295-monitor-p2.asm mon_scorp295_p2.bin \
    ../prof/scorpion-prof401-monitor-p2.asm mon_prof401_p2.bin
python3 auditblocks.py \
    ../base/scorpion-monitor-p2.asm ../base/scorpion295-monitor-p2.asm \
    ../prof/scorpion-prof401-monitor-p2.asm
```

Adding a fourth monitor version: `extract.py` (add the pair),
`analyze.py` -> `fixblocks.py` -> `renblocks.py` for its block map,
`align.py <new stem> dict_scorpion.py` for the symbol map, then write a
new `dict_<version>.py` following the two existing sisters.

## Invariants and conventions

- A listing is correct only when `checkcov.py` reports 16384/16384 and
  `auditblocks.py` reports 0 unnamed block headers.
- No `blkNNN` auto names may remain anywhere in the `.blocks` files.
- Labels are PascalCase; block names are meaningful (`FillerXXXX` and
  `MsgXXXX` name genuine padding/inline strings).  The `Tok*` names are
  the one deliberate family (tokenizer records).
- `gen.py`, `checkcov.py` and `auditblocks.py` take explicit paths and
  never write next to the inputs; `fixblocks.py`, `renblocks.py` and
  `extract.py` operate on files in this folder (`renblocks.py` keeps a
  `.bak2` on first change; `fixblocks.py` does not - use git).
- Both sister dicts must build with zero `WARNING:` lines; a dropped
  comment means an address needs a hand-resolved symbol or a local
  comment.
- The pipeline regenerates the committed listings byte-identically;
  `diff` the output against `../base`/`../prof` after changes.
