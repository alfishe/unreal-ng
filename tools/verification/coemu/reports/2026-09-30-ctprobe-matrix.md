(`tools/verification/coemu/run-all.sh`) on every emulator it found, each with its stock settings, 2026-09-30.
All emulators ran the same probe build. Expected values come from the probe's hardware-derived tables for the
machine class it detects.

The number of checks differs by machine: paging checks run only where #7FFD paging works, the +3 layout checks
only on the +2A / +3, and the floating-bus checks not on the plain clones.

## What the main differences are

| Emulator | Where it differs |
|:--|:--|
| FUSE | +2A / +3: the gate array's extra wait at the end of each line is missing (1 value) |
| SkoolKit | the floating bus: unused ports always read #FF |
| xpeccy-plus | 128K / +2: a port whose high byte points at an odd page at #C000 does not wait; +2A / +3: the waits come 2 ticks late, the extra tick at the end of each line is missing; Scorpion: the floating-bus check 2 ticks late |
| Xpeccy | 48K / 128K / +3: many values differ |
| MAME | 128K / +2: everything 2 ticks late; +2A / +3: the waits 4 ticks late, port accesses wait |
| ZEsarUX | 48K / 128K: the floating bus only; +2A / +3: the waits 4 ticks late, internal ticks wait |
| ZXMAK2, Kozynax | 48K / 128K: everything 1 tick late (the stock ULA is the "late" one); +3: the 128K's pages wait, the +3 layouts, the floating bus. Kozynax's dumps are byte-identical to ZXMAK2's |
| ZX-M8XXX | internal ticks of indexed instructions, `CPIR`, `EX (SP),HL` and chained prefixes; the port cycle of `IN r,(C)` and block I/O placed early; on the 128K ports never wait and there is no floating bus; its Scorpion is timed as a Pentagon (no Even M1, no attribute bus) |
| spec_chum | 48K / 128K: internal ticks (an address on the bus, no memory access) never wait; +2A / +3: the 128K wait pattern, so the probe finds a 128K |

## The errors

| Emulator, machine | Why |
|:--|:--|
| MAME, ATM Turbo 2+ | the machine boots at 7 MHz; the probe stops and asks for 3.5 MHz |
| ZEsarUX, ZX-Evo | BaseConf does not boot: no text on the screen 30 s after power-on |
| spec_chum, Scorpion | the program never loads: its TR-DOS ROM stays paged in after a call through RAM |

Each runner's README (`tools/verification/coemu/<emulator>/README.md`) explains its differences value by value;
the check-by-check view is in [2026-09-30-ctprobe-matrix.html](2026-09-30-ctprobe-matrix.html) next to this file
(generated by `../matrix.py`).
