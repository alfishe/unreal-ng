# E7 — Write journal retention

Part of the [TTD v2 experiments](../README.md). Design under test: Phase 3, Step 7 of the [migration](../../../../../docs/inprogress/2026-09-25-ttd-v2-migration/phase-3-replay-inputs-tdd.md#48-step-7--the-write-journal-as-a-derived-index): the write journal as an index that a replay can rebuild, kept by a retention policy.

Results and conclusions, in plain terms: [write-journal-e7.md](../../../../../docs/inprogress/2026-09-25-ttd-v2-migration/write-journal-e7.md). Full tables per session: [results.md](results.md).

## Goal

Choose how much write journal the engine keeps. Candidate policies:

- Ring: the newest 8,388,608 records, as v1 does.
- WholeHistory: every record.
- Window W: the records of the last W frames; W = 0 keeps none.

Each is judged by memory and file bytes per minute against the time of the find-last-write queries it cannot answer itself.

## Method

- **Input sessions** ([record-sessions.sh](record-sessions.sh)), recorded with a 1 GB journal ring so nothing is lost:
  - the six real-use sessions of E6, 1 and 5 minutes;
  - 48K at the BASIC prompt, ATM Turbo 2 (v4.50), and ZX-Evo with General Sound 512, MoonSound or TurboSound FM, 1 minute.
- **Measured costs** (`TTDE7` in `core-benchmarks`, `UNREAL_TTD_E7_DIR=<folder>`):
  - the coverage index walked over the whole session, per frame;
  - one frame's writes regenerated by replay (`TimeTravelManager::RegenerateFrameWrites`), p50 / p99 over 200 frames.
- **Exactness check:** those 200 frames per session, regenerated writes against the journal's records.
- **Model** ([model.py](model.py)):
  - bytes per minute per policy, in the engine's record format (memory writes only, columns, zstd level 1, blocks of 2,048 records);
  - for 1,000 find-last queries per session: answered from the kept journal, or how many index frames are walked and frames replayed (at most one).
  - Query addresses come in three classes: written in the last frame, 1-60 seconds earlier, more than 60 seconds earlier or never.
- **[run.py](run.py)** combines the model and the measured costs into [results.md](results.md).

## Run

```bash
./record-sessions.sh                                   # ~30 minutes, ~1.5 GB in scratch/ttd-experiments/e7/
for L in 1min 5min; do
  UNREAL_TTD_E7_DIR=../../../../../scratch/ttd-experiments/e7/$L \
    ../../../../../cmake-build-agent-release/bin/core-benchmarks --benchmark_filter=TTDE7/ \
    --benchmark_format=json --benchmark_out=../../../../../scratch/ttd-experiments/e7/$L/e7.json
done
python3 run.py                                         # ~30 minutes on a loaded host
```

Timings need an idle host (load average under 12), run twice. The current [results.md](results.md) comes from a loaded host (`e7-loaded.json`, load 20-40); its byte columns and exactness do not depend on load.
